## 1. 计划定位与边界
`RR` 只表达路线位置（Stage 7 之后、Stage 7.5 之前），不是 Stage 7 的子阶段，也不改变 Stage 8–14 的编号；与 [Stage 7-RPA 计划](../../completed/stage-07/05-rpa-new/plan.md)不是同一对象。本阶段不重开 Stage 7 的受限退出判定，不改写其历史失败、未认证范围或 testOnly 状态。

```text
Stage 7（受限退出） -> Stage 7-RR（本阶段） -> Stage 7.5（Gameplay Evolution） -> Stage 8
```
[Stage 7.5 计划](../stage-07-5/plan.md)的入场前置已包含“本阶段当前计划范围完成并取得 owner 接受”；本阶段交付复核、合同收敛、结构清理与已接受的新玩法实验实现，不决定 Stage 7.5 的能力范围或实施顺序。

- [发现登记册](findings.md)是问题与证据状态的唯一清单；本计划不复制其正文，只用 ID 引用。`docs/stage_reports/stages/stage-07-rr/` 下的报告是证据，不是权威。
- 本计划唯一确定实施范围与授权；调度、任务步骤和阶段验收各由 §6、§7、§9 路由；发现仍回写 findings。

- **用词。** 接受指 owner 对方向、合同或阶段结论作出裁定；采用指派单时把候选包绑定到具体基线、写域与验收。已接受不等于已实施，采用不等于发布。减重选项写“选项 R1–R6”，工作项写“RR-0–RR-6”。构建统一写“默认构建”或“候选构建”，`experimental` 只作目录、命名空间或标识符。旧 Packed 产物写“编译成品”，后继拥有型输入写“准备内容”。本计划不决定 SDK minor、发行版本号、合并与发布；稳定 C ABI 归 Stage 14，需要修订 ADR/Spec 时按第 10 节由 owner 接受。
## 2. 阶段目标
### 可验收成果
1. **结构证据与减重决策**：交付依赖分层、格式线、时间源、渲染路径、会话层次与公共 API 面的代码证据；对每个合并/下沉/删除/标 candidate 的对象，另行交付具名决策、受影响合同、历史证据处置与回归证据；判定：RR-0 研究/证据报告落盘，RR-3/RR-4 退出报告与删除/合并清单可逐项核对。
2. **状态与合同一致**：现行文档不再与版本、分支、阶段归属、格式状态和 SDK 陈述冲突，历史值显式标为历史；“文档承诺存在而实现不存在”与“实现比文档更严/更松”两类条目一并订正；确实无法实现的标为未实现；判定：RR-1 文档门禁全过且无事实冲突，RR-2 每条有 Spec/ADR 裁定或“未实现”标签。
3. **失败语义统一**：同一失败在文档、实现与宿主观测面得到同一个稳定码，静默失败被消除或显式登记；判定：RR-2 的正反 fixture 与受影响测试通过。
4. **交接可接手**：结论、处置理由与残留缺口写入 Stage 7.5/Stage 8 交接，不留在会话记录里；判定：RR-6 退出报告与 HANDOFF/CURRENT_STATUS 指针一致。
5. **统一实施与实验验证**：T-10–T-16 与现行修复一同进入本轮，验证 v3 源编译、成品、会话、Player 与写回；F302、F310、F313/F316、F207 全面清理按 §24 裁定纳入对应任务。Stage 8 按续议决定将 v3 收敛为正式主线；RR 实验结果不等于实际发行或旧公共接口退役。

### 非目标
- 不追求“所有 P2 清零”或“结构无技术债”；P2 可 deferred，但须写明归属阶段与恢复条件。
- 能力变更限本轮已接受的 v3、时间/成品、呈现/Player/Writer 合同与具名修复；默认 SDK 晋升、正式发行和设备性能保证仍需独立证据，不由任务纳入自动成立。
- 不为行数预算拆文件；owner 已取消纯行数拆分，行数只作为 findings §4 的事实记录。
- 不删减历史证据来让文档“看起来瘦”；减重不等于删证据。

## 10. 回滚、阻塞与停止条件
1. 合同变更未取得接受：停止受影响实现，保留最小复现，回到最后接受的 revision。
2. 确定性失败（跨编译器/平台差异、未声明浮点、溢出、容器顺序依赖）：阻塞该批，不以“环境差异”放行。
3. 预算/容量失败：区分内容、稳态、快照与 Replay；不得事后缩小 fixture 或改口径。
4. 安全失败（不可信输入导致未界定循环/IO/过量分配）：稳定拒绝并保留完好的旧加载版本；涉及 D-13 Reload 时仍须停止播放与判定，保留版本不表示继续运行。
5. 集成失败：回滚新增入口，不删除旧路径；旧路径的退出按 [ADR 0041](../../../adr/0041-legacy-format-exit-policy.md) 单独排期。
6. owner 未接受 ADR/Spec/例外：状态保持 planned/active/blocked，不把“待决定”写成已完成。
7. 触发范围或版本越界：停止该对象变更，按 §4 处理；不得仅凭长期设计改变延期状态。
8. 证据路径移动或已归档报告被改写：立即停止并回滚；不得用更新 manifest 来“修复”历史证据。

- **不做纯行数拆分**：owner 已取消，详见 D-03 与 §2 非目标。

- **不重跑、不改写历史失败与未认证范围**：不提高 caps，不补造证据，不把旧失败改成通过。
- **旧窗口、wire 与 identity 按旧版本保留**：本轮新版本按已接受的实验合同实施；超出该合同的语义变更仍按 D-04 先裁定。旧格式兼容证据归 T-01/T-10/T-13。

- **不移动 tools 证据套件目录、不改写证据 manifest 路径、不重写已归档报告**；证据套件原位冻结。
- **旧路径**：[stage_plans/legacy-paths.md](../../legacy-paths.md)只登记旧路径映射，不在本计划重写合同；Stage 7 的 completed 计划与报告保持原位。
- **旧格式退出**：Chart v1–v4、CXT v1、CXC v1 等由 [ADR 0041](../../../adr/0041-legacy-format-exit-policy.md) 约束；不缩短兼容窗口，除非 owner 另有决定。
