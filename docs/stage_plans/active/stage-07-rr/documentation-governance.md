## 1. 计划定位与边界

本方案是 [RR 总计划](plan.md)下的文档治理分册，属于 RR 的状态事实对齐、文档减重及退出验收工作。它补齐现有政策与执行之间的缺口，并先以 RR 文档和后续新增文档试行；阶段范围和任务采用统一回归 RR 总计划，G-01–G-05 只表达 T-18 内部检查点。

分册沿用初稿元数据 ID，文件位置与导航按当前 RR 归属更新。初稿从未提交或发布，调整后的引用直接指向本页，不重复保留初稿副本。

### 与相邻阶段/分册的关系

```text
方案审阅与接受 → 明确启动 → 规则收敛 → 校验与迁移 → 独立复核 → 交接
```

通用规则已归 DOCUMENTATION_POLICY，操作入口归 BUILDING，工具职责归 tools/README；本方案保留整改安排和验收，后续维护直接修改对应正式文档。

### 本计划不直接决定的事

产品功能、格式兼容、已接受设计和实际发行继续按原合同裁定。文档检查通过仅证明对应检查范围成立；产品行为须由实际实现、测试及必要的设备证据支持。

## 2. 阶段目标

### 可验收成果

| 成果 | 完成判据 |
| --- | --- |
| 统一文档职责和例外 | 每类文档有明确用途、存放位置和权威范围，例外可定位 |
| 登记册可检查 | 发现定义唯一，引用可解析，证据和处置字段完整，原始发现受到保护 |
| 命名与报告归类可检查 | 新增文档及采用新布局的目录遵守明确规则，已登记历史例外仍可读取 |
| 单一权威可追踪 | 重要合同主题有唯一拥有者，摘要回链，重复内容疑点能复核 |
| 检查结果说明实际覆盖 | 明确区分通过、失败、未检查和不适用，不把未运行项计入通过 |
| RR 报告完成分类整理 | 报告、引用、导航和旧路径映射一致，历史结论及原始附件可追溯 |

### 非目标

不追求把全仓历史材料一次性重命名，也不建立文档数据库、通用工作流引擎或每条要求的独立登记文件。优先扩展已有 Markdown 元数据、校验器和测试，控制长期维护内容。

## 5. 假设、约束与风险

| 风险 | 失效信号 | 缓解/回滚 | 责任 |
| --- | --- | --- | --- |
| 新规则误伤历史材料或模板 | 原始附件、模板示例被当作现行合同 | 明确适用范围及精确例外，增加合法样例 | G-01、G-03 |
| 整理改变发现和历史结论 | 旧发现文字、原报告结果或附件字节发生改变 | 比较冻结输入，恢复原文；事实纠正另作记录 | G-02、G-04 |
| 迁移破坏链接或身份 | 原入口失效、ID 随路径改变 | 同批改引用，保留稳定 ID、路径映射和快照身份 | G-04 |
| 检查通过被扩大解释 | 缺少测试仍宣称功能完成 | 输出覆盖范围，验收表记录实际测试与缺口 | G-03、G-05 |
| 规则产生额外文档负担 | 每个字段、命令或子任务都新建清单/报告 | 复用原文档和已有验收表，仅登记关键主题 | 集成者 |

**不可逆点**：本工作包主要是可回滚的仓内修改；历史报告链接可能已被仓外使用，路径移动仍有兼容影响。批量迁移提供映射，但不承诺每个旧 URL 继续有效；确认有外部依赖的入口需保留兼容路由或暂缓移动，并在交付中点名说明。

## 7. 分批细化

### G-01：文档职责、命名和适用范围

正式政策使用下列职责划分；已有目录继续承载原角色。

| 文档 | 主要职责 | 更新方式 |
| --- | --- | --- |
| ADR、Spec、API | 设计决定与接口/格式合同 | 修改对应拥有者，摘要只回链 |
| CURRENT_STATUS | 当前阶段、进度、遗留 | 更新当前摘要，不累计操作日志 |
| HANDOFF | 本次任务、下一步、阻塞、验证状态 | 收尾更新，不代替阶段状态 |
| plan / task / schedule / acceptance | 范围、操作、依赖、阶段验收 | 继续沿用现有拆分，各自只维护所负责内容 |
| findings | 原始发现、核验、处置与责任 | 定义唯一，后续引用 ID，处置有据 |
| stage_reports | 带日期的研究、实施、测试和交接证据 | 保留当时结论，新证据明确对应后续修订 |
| README、MAP | 导航与路由 | 总索引不重复阶段结论、报告数量或测试矩阵 |
| archive、原始附件 | 历史资料和原始证据 | 保留原始日期、身份及字节 |

命名规则按文件角色检查，报告日期还须验证真实日历日期，不能只匹配数字形式。

| 对象 | 命名 | 例外与边界 |
| --- | --- | --- |
| 新建常规 Markdown | 小写 `kebab-case.md` | 稳定入口及下列角色规则优先 |
| 主计划及配套入口 | `plan.md`、`schedule.md`、`acceptance.md`、`findings.md` | 不重复附加日期 |
| 任务卡 | `T-xx.md` | 沿用已有任务 ID 规则，不强改为小写 |
| ADR | `NNNN-short-title.md` | 编号唯一，主题为小写 kebab-case |
| 新增报告正文 | `YYYY-MM-DD-topic.md` | 涉及单一任务时可写 `YYYY-MM-DD-t-03-topic.md`；命名示例不代表已有产物 |
| 导航与历史映射 | `README.md`、`legacy-paths.md` | 仅出现在实际需要导航或映射的位置 |
| 模板、原始附件及历史文件 | 按角色识别 | 模板例子不参与身份登记；原附件不强行改名；已有历史路径精确保留 |

例外只登记已存在的具体路径和理由，复用检查器的小型规则配置，不新增一份全仓文件清单。新增路径、复制文件或改名不会继承旧例外；历史内容保护也不会因命名例外失效。已有稳定大写 Spec 可暂保留，涉及实质重组时再处理。

本批同时解决“按用途分类”与报告索引中“不迁移”的冲突：允许有映射、有引用校验且不改历史结论的文档迁移；原始证据附件仍受字节保护。政策日期记录本次规则修改时间，不把历史报告日期统一改成当天。

### G-02：发现登记、证据与处置闭环

继续用 Markdown 作为唯一登记正文，不另建与之同步的 JSON 数据库。为真正定义发现的表格增加一个紧邻的轻量标记 `<!-- cuexis-findings: definitions -->`；校验器只在该标记所指的下一张表中读取定义，修复清单、承接表和正文中的 ID 均为引用。标记不能跨章节作用于后续全部表格。

定义表统一为“ID、原始发现、原始依据、核验状态、处置状态、责任/任务、当前处置依据”几列。迁移可以整理表格语法和拆出混合列，必须逐条保留原始断言及最初证据内容，不能借字段整理改写判断。表格解析须识别转义分隔符和代码跨度，不能简单数全部竖线。

| 检查对象 | 硬检查规则 | 需要人工核实的部分 |
| --- | --- | --- |
| 身份 | 定义编号唯一，格式合法，既有编号不重排；引用能找到定义 | 两个不同编号是否描述同一问题 |
| 核验状态 | 固定为“未复核”或“已核实”；已核实有具名复核者和证据 | 证据是否足以支持原断言 |
| 处置状态 | 固定为“开放、处理中、已修、已处置、延后、撤回” | 已处置是否获得所需接受 |
| 原始依据 | 有可定位的来源和适用修订/快照；无法确定时明确写未知并保持开放 | 原实现或外部审查资料的真实性 |
| 开放/处理中 | 有责任任务或明确的后续核验归属 | 处理方案是否充分 |
| 已修 | 有核验、改动修订、实际验证及关闭依据 | 验证是否覆盖原缺陷、是否有回归 |
| 已处置/撤回 | 有核验、理由及决定/反证记录 | 是否改变了已接受合同或兼容承诺 |
| 延后 | 有责任阶段/工作包、恢复条件及决定依据 | 延期是否被接受，责任是否可履行 |

“已核实”只表示核验，不再混作关闭状态；旧条目按原证据映射，不能因整理直接升级为已修。若原文写 owner 已确认却缺少依据，保留该历史说法并标明当前无法核实，不伪造确认。

保护对象是既有 ID、原始发现和首次证据；当前责任、复核结果和处置允许更新，每次更新保留可追踪依据。撤回或重新打开也保留旧处置和原因。对原断言的事实纠正追加“订正”并指明替代关系，旧断言仍可读取。已关闭的日期报告需要新结果时另作后续记录，不覆盖旧结果。

首次迁移对冻结输入逐条人工核对，登记映射和例外；该次转换不能用新生成的摘要哈希自证无误。后续检查比较解析后的受保护字段与可信 Git 基线，合法换行或表格转义不算改写。CI 基线从工作流事件确定的基准修订取得，本地使用同一规则；缺少 Git 历史时明确失败或未检查，不能返回保护已通过。首次迁移例外绑定具体迁移修订，不能成为长期关闭保护的开关。

### G-03：元数据、唯一权威、重复检测和检查入口

真实文档只登记头部的实际 `cuexis-meta`，忽略代码围栏、模板及正文演示。检查单个元数据块、重复键、ID、状态、authority 以及角色间的合法组合；报告声明 `evidence/none`，索引声明 `index`。ID 在真实文档间唯一，移动文件保留 ID；模板占位 ID 不能被生成地图当作真实拥有者。

状态词、权限和例外在检查器内使用同一份规则定义，由各入口复用。新的候选方案可以无权威，但不能自动覆盖 accepted 合同。实现、验证和发布分别表述：candidate 可以已有实验实现；需要报告的是无对应实现证据却声称已实现，或将候选实验验证冒称正式支持，是否失实仍须核对实现与验收。

重要合同在原拥有者的元数据中增加可选 `topics`，列出稳定、含版本范围的主题键，例如 `chart-v5.render-alpha`。同一主题只允许一个有效的 `authority: owns` 文档。候选修改同一合同尚未接受时引用原拥有者；旧版本和新版可各自拥有不同主题。先覆盖本轮核查涉及的关键格式/API主题，后续修改合同顺手补，不给每个段落单建 ID。主题键能检查归属冲突，不能自动发现换名后的同义主题，后者仍属审查职责。

可选表示尚未纳入治理的主题可以暂不登记；未登记部分明确报告“未覆盖”。一旦主题进入治理范围，其登记必须持续保留：删除或改名主题、改变拥有者权限、转移文档时，须通过可信基线比较验证替代拥有者和具名变更依据，不能靠删掉 `topics` 退出检查。首次纳入的关键主题范围在 G-01 的基线记录中固定，复用政策和 Git 差异，不另建第二份拥有者清单。

重复检测先覆盖本轮变更的现行摘要和合同，对规范化后完整相同的较大表格或整块正文给出疑点及两端路径。报告快照、模板、生成视图、代码示例与短流程存在合理重复，按角色区分；不以模糊相似度直接阻塞。若确认是越权复制，摘要改为链接；合法重复给出理由，仍可继续验收。无需引入向量库或全仓 AI 相似度服务。

`status_contract.json` 改为校验当前结构化入口及其指向：阶段取 CURRENT_STATUS 的 `current_stage`，工作项和登记册指针必须存在且相符。移除当前摘要被迫保留旧 Stage/CFU 句子的要求。确有价值的历史断言只在相应历史证据范围校验；日期检查按文档角色说明用途，不能只更新 snapshotDate 冒充状态治理完成。

本地和 CI 使用现有总入口及共享辅助模块，按下表清楚区分证明范围。纯文档结构检查无需完整构建；需要 CMake 生成事实或产品测试时单独报告。

| 层次 | 职责 | 结果要求 |
| --- | --- | --- |
| 文档结构 | 链接/章节、身份、命名、调度、报告布局、登记册 | 可确定的违反导致非零退出；检查器本身异常也失败 |
| 代码派生事实 | 生成页、版本、预算、参数、诊断、target 等对照 | 所需输入齐备才通过；缺少事实文件显式标未检查；严格入口缺输入即失败 |
| 功能语义 | 实际模块正反测试、独立预期、必要的兼容/设备验证 | 引用对应修订和命令结果；不因字符串相符就认为行为通过 |

版本漂移结合文档角色和明确的历史语境处理，不能靠整行含一个“旧”字就放过当前断言；当前权威值冲突须失败，历史叙述允许保留原值。

agent 修改完成前运行适用入口，HANDOFF 和交付报告写明执行结果及缺口；无 push 也须遵守。保留现有 CI 独立调用，验证其使用相同核心规则。实际 hook 是否安装单独说明，hook 只作辅助。仓内脚本无法强迫任意本地 agent 执行，远端是否要求检查通过才可合并取决于仓库设置，未经核实不能宣称已强制。

辅助代码放在现有 `tools/verification/`，由 `tools/check_docs.py` 与事实入口复用；只在职责确实独立时拆模块。自测使用临时目录和内存反例，不能为证明拒绝而污染原始资料或正本。

### G-05：关键承诺与验收证据追踪

在现有 acceptance/任务验收表中补“合同章节、实现符号、正反测试、实际运行修订、命令与证据、未覆盖边界”。一行代表一个可以验收的行为，不要求所有说明性句子都有测试，也不另建全仓需求追踪系统。

优先覆盖本轮反复出现的关键承诺：新格式接受/拒绝集、旧内容直读与规则保持、Player/SDK 等待责任、覆盖登记原子性、公共边界。已有测试就复用；尚未实现的产品能力明确保持待实施，不把治理验收变成提前执行全部 RR 产品任务。治理工作包验收检查映射真实、缺口明确，以及已经作出完成声明的行为有对应证据；不能预认证未来功能。

审查者对关键样例读取合同、实现和测试预期，并运行允许范围内的代表用例。预期值应独立于被测实现，引用一个不存在或未运行的测试不能作为完成证明。完整构建、设备/容量探针及 hosted 长任务继续遵守现行长任务约定，未执行时明确保留缺口。

## 9. 验收标准与验收矩阵

以下是 T-18 的验收要求；实际执行、结果和未覆盖范围集中在治理交付报告，规则存在本身不构成通过证据。

| 验收项 | 正例 | 必须拒绝或明确报告的反例 | 判定方式 |

## 10. 回滚、阻塞与停止条件

1. 原始发现、历史结果或附件不能与输入基线对上时，停止受影响迁移，恢复原件，先核实差异。
2. 新规则与已接受合同冲突时，仅暂停受影响切片；由 owner 裁定合同变化，其余独立工作继续。
3. 校验器误报合法历史内容时，先修正规则或登记精确例外，不把错误隐藏为全目录豁免。
4. Git 基线、生成事实或测试环境缺失时，明确标未检查；严格验收保持失败或未完成，不补写通过。
5. 迁移回滚按路径映射恢复文件及相关引用，生成物重新生成；只回退本工作包改动，保留同期他人修改。
6. 本轮已明确授权实施 T-18；已接受范围内的常规步骤继续推进，不重复请求同一授权。
