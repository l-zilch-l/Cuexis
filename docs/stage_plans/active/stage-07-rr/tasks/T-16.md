## 写域

合同点名的 `engine/chart` 私有 writer/migrator 与具名仓内调用方、`tools/chart/chart_migrator` 帮助/退出行为、对应 round-trip/CLI tests 和格式说明；无公开编辑器 SDK 入口。进程验收写域含根 `CMakeLists.txt` 及对应 CLI 测试。P5-06 在本卡只验 `cuexis_chart_migrator`；编译/打包三个具名程序由 [T-13](T-13.md#任务级验收) 验。

P5-03/04 的测试写域明确包含 `engine/chart/src/chart_writer_internal.hpp`、`chart_writer.cpp`、`engine/chart/CMakeLists.txt`、`tests/chart/{chart_writer_tests.cpp,CMakeLists.txt}`。按合同在同一 checked-write 实现接按调用传入的私有 hooks；测试访问重载仅在 CUEXIS_BUILD_TESTS 下编入，不改静态 ChartWriter 的生产签名或安装/导出面。

## 步骤

按合同签名落地两个源模型和显式版本；v4 单轴编辑从编辑后继承及 overrides 的原 JSON 容器合成合法整向量 patch，保留未编辑参数引用，不能从 typed 占位回写或生成 /position/0。按字段和路径构造损失，迁移调用方后删除具名旧 helper。Writer 将 `text` 和 `losses` 返回调用方。仓内迁移和打包工具拒绝交付有损成品；编辑器是否确认后覆盖仍由编辑器决定。按[工具外部行为](../contracts/render-player-writer.md#工具外部行为)保留迁移单输入及显式输出/报告参数，单独 `--help` 输出 stdout、退出 0；混用仍属参数错误；一次命令结束即退出，成功 0、失败保留具体 1/2 分类、既有诊断码和路径。沿用现有双临时文件、备份、发布顺序与恢复尝试；恢复本身失败时保留可用备份、失败阶段和系统原因。

## 任务级验收

P5-03 在栈上建立 WriterTestHooks，通过非安装 WriterTestAccess 的同型重载注册到这一次调用，afterEncode 仅从产物 DOM 按 ID 去掉 name；实际 Reader 与 fidelity 比较保持运行。P5-04 在 BeforeEncode/BeforeSerialize/BeforeCompare 各一次注入 bad_alloc、length_error 和其他异常，分别断言 allocation_failed、limit_exceeded、unexpected_failure，无 text；关闭 hook 的下次写回成功。另用合法 v3 typed 输入、maxInputBytes=1 验真实输出预算，两处 name 损失配 maxDiagnostics=1 验损失预算硬失败。沿原 cuexis_chart_tests 注册 rr_chart_write，headless 不依赖 CLI/SDL/GL。进程 P5-06 的损失由实际有损源触发，不用这组进程内 hook 代验 CLI。

实施时新增、当前未执行：在 `headless-debug` 先构建 `cuexis_chart_tests`（库用例宿主），再用 `ctest --test-dir out/build/headless-debug --no-tests=error -R '^rr_chart_write$'`，执行[向量 P5-01–05、P5-07](../contracts/render-player-writer.md#验收向量)。v4 BPM 改至 150 后应重读为 150；v3 写后注入遗漏 `.name="edited"` 仍返回合法 `text` 及 `WriterNotFaithful/field_omitted`，库层验证该损失可供调用方拒交，真实 CLI 拒交及文件不变在 P5-06 验。Animator 新增/替换按 P5-05 用真实 `ChartV4Resolver::resolve` 验证最终 layer；保留悬空 `replace` 的对照须报 `chart.patch.target_missing`，不以 Loader 重读通过替代。P5-07 父 position=[0,param(y),0]、实例只改 X=5，输出 replace /components/cuexis.transform/position 且 value=[5,param(y),0]；分别以 y=2/9 跑 Resolver 得 (5,2,0)/(5,9,0)，losses 空。已有 overrides 和同次父 Z 编辑各保留；/position/0 阴性由原 patch Reader 拒绝，占位向量阴性须被双参数解析对照发现。

同一 headless 库用例另直接调用迁移入口，核对 `ChartMigrationResult.diagnostics` 中 `data_loss` 的去重 fieldPath 及 kind/detail/source；失败时 `artifact=nullopt`，无 report/discardedFields。两阶段同一损失合为一条 diagnostics，来源 conversion,writer；不新增失败报告字段。

另在 tools=ON 的 `candidate-headless-debug` 执行 `cmake --build --preset candidate-headless-debug --target cuexis_chart_migrator`，再跑 `ctest --test-dir out/build/candidate-headless-debug --no-tests=error -R '^rr_chart_migrator_cli$'`。本卡在根 CMake 新注册该测试，传 `$<TARGET_FILE:cuexis_chart_migrator>` 的同树路径；程序缺失即失败，不走 PATH 或跳过。实际子进程在隔离目录记录 stdout、stderr、退出码及目录/文件前后字节：单独 `--help` 只向 stdout 输出帮助、无文件副作用，混用帮助向 stderr 输出 usage 并返回 2。P5-06 迁移分支：帮助 0、成功 0、迁移损失失败 1、参数/读取/路径/提交失败 2。成功报告形状/golden 保持。提交前拒交时已有输出/报告不变。分别注入新报告发布失败、恢复操作失败；前者验证恢复原双目标（原无新输出时撤销），后者验证备份仍可用、阶段/路径及实际系统错误保留。两者退出 2 且不改输入。进程断言使用实际 stdout/stderr、退出码和文件，不以内存结果替代。
