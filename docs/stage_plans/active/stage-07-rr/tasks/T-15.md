## 步骤

按合同注册 CLI、接 `--aspect`、`--rotate` 与 `--keymap`，追加 `PlayerInputAction::Retry=7`、`WindowKey::F5=8` 并接 SDL 物理键：R 映射至 T-14 已定义并由生产 owner 消费的 `PlayerCommandKind::Retry`，F5 映射至既有 `Reload`。本卡不定义生产命令枚举或第二个 Retry 事务。按合同的载体/目录 producer/实际 Reader 工厂矩阵接入工程/CXC 条目选择及固定身份；后继 v2 工程/CXC 首次选择均要求显式 path（单项或 bootstrap 同值也一样），旧普通 bootstrap 及 v1 工厂保持原接受集，旧缺 bootstrap 保留 Reader 错误。松散 v3 源目录须由作者/fixture 显式写入 project 的 v2 extension，assembler sidecar 不自动发现；调用 T-13 的 owning artifact adapter，接入 T-14 的状态矩阵、首次失败恢复、纯画面重建和无音轨结束事实。落实 [D-16 外部行为](../architecture-design.md#外部行为2026-11-21-owner-已接受拟实施)：语法错误无窗口、stderr 诊断、非零退出；帮助正常退出 0；加载失败保留错误窗口、真实原因与详细诊断；合法内容能力不足不报未知参数或包损坏，不降级。关闭时按尚未恢复的加载/运行故障决定退出码。仅观察参数可同普通播放/正式判定组合；手工时间、输入注入和玩法覆盖只走显式测试入口，原不相容请求继续拒绝。开发 wrapper 与正式入口接入同一生产控制路径且不绕准入，保留原 test-only 回归；普通无来源保持可关闭窗口。键位处理按具名 token 表适配 SDL，准入不改变 SDK 标准逻辑输入或作者规则。只有完整通过能力/容量、冲突、未知 pair 和缺失 pair 校验才锁定配置；首次未知逻辑 pair 失败后的 F5 重读配置文件。

按[命令与启动](../contracts/render-player-writer.md#命令与启动)将 `namedKey` 改为接 SDL_Scancode，并从 pollEvents 传 event.key.scancode，全部保留控制键都按 SDL_SCANCODE_* 映射，不能仅加 SDLK_F5。修饰键按下只抑制 named command，保留 raw 玩法事件；Player surface 先剔除保留键的按下/释放再投递玩法。T-14 的准入纯值和 owner 成功策略在本卡仅消费，首次无 A 的 Failed+有来源 F5 可恢复，Empty+无来源仍拒绝。

新增测试的 `PRIVATE SDL3::SDL3` 链接时，同卡在根 `cuexis_verify_target_dependencies(cuexis_platform_sdl_tests ALLOWED ...)` 追加 `SDL3::SDL3`，保留原两项。按依赖政策在既有 SDL3 登记中注明 `cuexis_platform_sdl_tests` 的事件注入用途及测试目标不进入分发；核验并记录现有 vcpkg feature/baseline、许可与安装清单的适用影响，沿用已有 SDL3，不因这一测试边新增 port 或修改公共传播边。重新配置 `candidate-debug` 通过实际逐边守卫后，再定向构建及执行下述平台测试。

接入 T-14 的设备等待行为：等待计时、超时判断及超时后处置由各平台 Player 实现和决定，可不设期限或设置适合平台的期限；SDK 不提供设备等待超时计时器、策略或默认期限，不因等待时长自行判失败。窗口沿既有非阻塞提交和轮询消费结果，在等待及超时后尚未收束时仍处理重开和退出请求；平台/驱动真实失败照常报告，实际关闭保留既有清理/ACK 规则。

本卡消费 T-14 已迁入 `app/player_support` 的同一目标与纯值命令，不恢复 `engine/player_support` 或新建第二份配置/状态实现。新增 Player 装配须满足[应用分层与内部入口](../contracts/render-player-writer.md#应用分层与内部入口f313f316)；门禁随 Player 交付再核最终全应用闭包。

先配置 `candidate-debug`，执行 `cmake --build --preset candidate-debug --target cuexis_player cuexis_player_control_tests cuexis_playback_tests cuexis_platform_sdl_tests`。以 `ctest --test-dir out/build/candidate-debug --no-tests=error -N -R '^(rr_player_startup|rr_player_commands|rr_player_physical_keys)$'` 核对三项均已注册，再去掉 `-N` 执行；以下同名用例均使用该 `--test-dir` 入口，不依赖 candidate preset 的默认名称过滤。

正式表无已验证行时为空，保留明确的能力拒绝。测试版注入 `rr.keyboard.fixture.v1` fixture 行（7 通道容量），经与正式版相同的匹配函数验证 4/6/7 通道。首个正式行随发行变更提交内容/编码/玩法版本及 profile、设备与时钟证据、实测容量和对应回归；用正式包重跑正例与错 identity/超容量反例，证明测试行 ID 与注入路径未编入正式构建。

实施时新增、当前未执行：分别运行 `ctest --test-dir out/build/candidate-debug --no-tests=error -R '^rr_player_startup$'` 和 `ctest --test-dir out/build/candidate-debug --no-tests=error -R '^rr_player_commands$'`，执行[向量 P4-01–02、P4-06、P4-08–10](../contracts/render-player-writer.md#所有权暂停与收尾)。无修饰的非重复按下 R/F5 各只送一条具名 Retry/Reload；配对释放和重复按下不再送命令。R 不重读，F5 重读并在零点暂停。P4-06 用真实目录及 Reader 验证：旧普通工程/CXC 省略选 bootstrap，删必需 entry.chart 报旧错误；后继 v2 工程/CXC 即使单条/等于 bootstrap，无 --entry 也 entry_required。受支持组合显式 `--entry charts/hard.json --judge` 只选 hard；删 hard 后 Retry 用缓存，Reload 报错并留 A 停播。开发 wrapper 与正式入口同输入时控制轨迹一致；P4-08 对照 Player 声明支持的载体，缺规则或身份错误不降级。CXC 源包合法性由 T-13 单独验收；参考 Player 不接后继纯源包播放，合法包报 `player.source.encoding_unsupported`。4/6/7 通道共用一次配置和准入过程；数字、标点、方向、功能键的正例及控制键冲突、重复/缺失/超限、运行中改配置的反例按 P4-09。增加首次 JSON/冲突校验已过但未知 pair 的失败：修正文件后 F5 必须重读并恢复 Paused@0；此时才锁定，后续改文件 Retry/F5 均不改变映射。
P4-01/02 必须包含：曾成功加载→后加载/运行失败未恢复→关闭非零；失败→Reload 恢复且静音零点暂停→关闭 0。另核对无参正常关闭 0、帮助退出 0、语法失败非零、合法但缺能力保留具体诊断、Stop/自然结束不强制关闭且正常关闭 0，以及普通拒绝控制命令不自动记为未恢复运行故障；覆盖仅观察参数组合及不相容测试请求反例。P4-02 证据另附 Reload 成功切换前 A+B 并存的进程峰值工作集（外部采样，只记录不设阈，预算归 Stage 7.5 GE-R）。

平台新增 Catch 用例名 `rr_player_physical_keys`，沿现有 `catch_discover_tests` 和 `SDL_VIDEODRIVER=dummy` 注册；构建 `cuexis_platform_sdl_tests` 后在 candidate-debug 执行同名 CTest。用 `SDL_PushEvent` 注入本窗口的 keycode/scancode 不一致事件：scancode R、keycode Q 仍只触发 R；scancode Q、keycode R 不触发 R；F5 同样按 scancode。遍历八个控制键、按下/释放/重复与 Shift/Ctrl/Alt/GUI，核对 pollEvents 的 named/raw 值。`rr_player_commands` 再经同一个 SdlPlayerSurface/commandForAction 验 Retry/Reload 及保留键零 gameplay transition；不以预造 WindowKey 绕过 SDL 代验。P4-09 的游玩键配修饰后释放仍恰一 Release。

- D-14 恢复输入归本卡：实时游玩因画面不可用暂停后，先用真实 `SdlPlayerSurface`/`commandForAction` 注入冻结画面确认前的 Space key-down，断言未获得成功的 Resume、无控制状态转移且 gameplay capture 零输入；冻结画面实际呈现并满足既有同局证明后，下一 Space key-down 才作为显式 Resume 提交，该按下和配对释放仍不得进入 gameplay capture，恢复确认前位置及判定 tick 为 0 增量。恢复成功后下一非保留游玩键仍可按原映射产生一次 Press/Release，证明恢复键路由没有吞掉后续输入。
- RR-F525 等待输入归本卡：沿已有 `rr_player_commands` 的注入时钟和可控设备回执，覆盖 Player 不设期限且回执未返回、等待超过 P4-03 的 500 ms 观测窗，以及 T-14 同设备回执时刻下短/长两种 Player 期限分支：短期限由 Player 判定超时，长期限在回执到达后正常完成。500 ms 仅为原观测窗口，两种期限仅为 fixture 值，不成为发布默认；SDK 不因等待时长自行判失败，平台/驱动真实失败仍按原路径呈现。真实窗口循环不得在 `PlayerController::apply` 内同步等待终态；热路径经既有 `OwnerChannel::post` 保存请求 ID，在主循环每轮用非阻塞 `poll/ack` 收束并共用唯一 owner，阻塞型 `apply` 只供可以等待的调用方。在无期限等待超过观测窗、长期限回执尚未返回及短期限超时后原事务仍未收束时，用实际 SDL 事件分别注入 R（Retry）和 Escape/关窗：两者都必须被窗口及时发现；R 只登记重开意图，旧事务尚未按既有取消/终态、清理和 ACK 收束前不得显示新局成功；退出请求无需等原事务终态才受理，实际关闭沿既有清理/ACK 规则。超时不得伪造设备取消完成、事务成功或新局；后继局或关闭后到达的旧设备/事务回执不得改变状态或结果，资源仍安全清理。该用例复用现有目标，不新增线程、控制器或队列，不放宽既有 deadline、receipt 或 ACK。
