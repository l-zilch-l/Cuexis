## 目标

`R5`；让同次提取的布局、快照和资源身份贯通 Playback、宿主和适配器，替代仓内具名旧调用。采用见[计划](../plan.md#唯一派单授权入口)。

## 输入

[渲染候选合同](../contracts/render-player-writer.md)、[D-23/D-25](../architecture-design.md#d-23-谱面画面比例与宿主尺寸)、[兼容政策](../../../../adr/0041-legacy-format-exit-policy.md)。

## 写域

合同点名的 Playback/GL 实验头与 TU、`app/execution_host` 请求、观察和呈现桥、Player 装配与帧循环、引用旧帧入口的具名探针、帧回归测试及相关合同。不改已装旧签名、不让执行宿主目标链接 OpenGL、不改格式。 R5 仅以旧 Reader 与内存规约画幅表验收，不依赖 T-11/T-13 或其测试 target；T-11/T-13 各自把新载体接到同一 `framings` 字段。

接 T-05 同一物理头与符号表。本卡改 `engine/playback/{CMakeLists.txt,src/playback_session_internal.hpp,src/playback_session_prepared.cpp,src/playback_session.cpp}`、`app/{player,execution_host}/CMakeLists.txt`、`engine/render_opengl/CMakeLists.txt` 及根 CMake、`cmake/VerifySharedExports.cmake`、对应源码/安装消费者。按[链接与安装合同](../contracts/render-player-writer.md#提交资源与交付)只给默认实际用头者 PRIVATE 根；实验 `PUBLIC FILE_SET` 安装同一个头。五个自由函数与表列帧成员用同一实现，两种 shared 逐符号导出，默认无新增 Gameplay/作者依赖。内部 shim 和私有构造不导出。

## 步骤

1. 接入合同的提交态画幅表与帧对象，现行 Chart 走 legacy 空表；内存注入有序多画幅，对比同一相机曲线的投影及 retained 重排；`FramePayload`/envelope 携带同次快照与布局，区分当前与 retained 的资源权属。 用 Prepared 和会话提交态的纯值 `framings`，不从候选 metadata 取画幅；提取在同一 owner 的一次 committed descriptor/Runtime read 中形成快照、投影、来源与 token。
2. Player 用最终位置的同一 `OpenGlBackend` 实例注入 `FrameLayoutRendererBinding`，普通循环与执行宿主都走合同所定装配。原请求 deadline 随 envelope 的 dispatch 元数据传递；overlay/hook 返回后 owner 重取完整 `FrameTarget`，通过 `presentOwnedFrame`/binding/GL 的合同参数传入，同一无回调区间逐字段核对 extent、host、rotation、路由、租约和时限。目标失配非故障弃帧，清 awaitingSuccess、保 retained，不触发设备暂停。
3. 按合同迁移启动占位及私有 smoke hook；借用探针与正式提交使用同一个 `LaidOutFrame`。保留正式旧入口，记录历史安装消费证据和后继退役条件。

上述步骤逐个落到[实际接线](../contracts/render-player-writer.md#提交资源与交付)：`presentation_materializer.cpp` 用 T-05 私有 helper 将最终 Pout 写入 camera.projectionMatrix；`session_worker_owner.cpp` 在原 reservation 内移动构造 variant 分支，`frame_observation.hpp` 统一 snapshot/layout view，`frame_delivery.cpp` 同步 payloadBytes/frameByteBound，`execution_host_frame.cpp::OverlayRenderer` 增 `submitLaidOut(frame,currentTarget)` 并转发同一个 binding。scene 在最终 gate 之前建好；`presentOwnedFrame` 按分支传完整 target，旧 adapter 用模板能力检测保持可编译。`snapshot_scene.cpp` 的 FPS 沿完整投影视图逆矩阵，窗口文字不随谱旋转。写域含以上 TU 及相应非安装测试；所有固定/动态计量只计当前 variant 的一份拥有值。

## 任务级验收

实施时新增、当前未执行：`ctest --preset candidate-debug --no-tests=error -R '^rr_laid_out_frame$'`，执行[向量 R5-05、R5-07–08、R5-10 的相机/retained 及旧入口对照](../contracts/render-player-writer.md#兼容目标及向量)。R5-05 的 legacy handle + layout 请求、layout handle + legacy 请求均为 `noRetainedFrame`，旧 handle 仍可用且不重采、不提交。R5-07 断言同一 backend；`deadline=100`，submit 前 99 提交/交换各一次，100 则报 `host.rpa.context_stale`（`reason=frame_deadline`）且零提交。另以 extent `1600×1000`、host 大小 `1280×721`，在取帧后把 host.x 从 100 改为 200，断言提交前 `frame_target_changed`、零 clear/submit/present/成功 receipt，旧 retained/serial 保持、无 renderer fault；下次新目标请求可呈现。分别覆盖只改 y/宽高/rotation，不能只比 extent。R5-08 对同一帧的两次借用均从本次 FBO 得到青色 RGBA，保留正式帧 digest；任一借用失败都不复用旧像素或提交正式帧。 比例和 rotation 随请求进入同帧投影，旧谱 0° digest 不变；BestFit 冻帧 resize 后重选、重投影，依据原采样、同资源与 token，零 Runtime 重采样。

本卡在根 CMake 新注册 `rr_frame_layout_shared`，以 `$<TARGET_FILE:cuexis_player>` 驱动该树的真实 Player。分别在 `shared-debug`、`candidate-shared-debug` 配置后执行 `cmake --build --preset <preset> --target cuexis_player`，按同配置安装闭包备齐归档/库，再用 `ctest --test-dir out/build/<preset> --no-tests=error -R '^(rr_frame_layout_shared|cuexis_shared_export_surface)$'`。两者以同一正式旧谱和固定采样、0° 走普通新路径，各提帧一次，对照同一旧谱基线 digest（两构建相同）。同版仓内消费者真实构造结果、移动构造/赋值、调用五个访问器、重排、析构；实验安装消费者 opt-in 后仅链接 `Cuexis::Playback` 复做。默认安装与普通 `add_subdirectory` 消费者分别包含 `cuexis/playback/experimental/frame_layout.hpp` 须因头不可见失败；默认旧头独立可用。两 shared 逐项比导出表：隔离副本各撤一个必需成员标注或多导出一个未列函数，应分别因缺符号/额外符号失败；不以仅检查命名空间或仅链接 static 代验。

R5-07 另经真实 worker→envelope→OverlayRenderer 驱动 legacy/layout 两分支；布局分支记录 binding 收到同帧地址、同完整 target 和预先生成 scene，submit/present 各一次。分别启闭 FPS、注入缺桥与目标变化，不能退回旧 submit；payloadBytes 与 reservation 比对，retained 别名不新增 payload 计费。R5-10 检查快照矩阵等于纯值 Pout，GL 只消费一次；旧谱 90°/270° 的点位及 0° 旧摘要均按合同核对，retained 反复重排无 Q/R 累乘。
