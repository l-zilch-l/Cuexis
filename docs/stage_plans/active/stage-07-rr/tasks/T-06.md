## 步骤

1. 接入合同的提交态画幅表与帧对象，现行 Chart 走 legacy 空表；内存注入有序多画幅，对比同一相机曲线的投影及 retained 重排；`FramePayload`/envelope 携带同次快照与布局，区分当前与 retained 的资源权属。 用 Prepared 和会话提交态的纯值 `framings`，不从候选 metadata 取画幅；提取在同一 owner 的一次 committed descriptor/Runtime read 中形成快照、投影、来源与 token。
2. Player 用最终位置的同一 `OpenGlBackend` 实例注入 `FrameLayoutRendererBinding`，普通循环与执行宿主都走合同所定装配。原请求 deadline 随 envelope 的 dispatch 元数据传递；overlay/hook 返回后 owner 重取完整 `FrameTarget`，通过 `presentOwnedFrame`/binding/GL 的合同参数传入，同一无回调区间逐字段核对 extent、host、rotation、路由、租约和时限。目标失配非故障弃帧，清 awaitingSuccess、保 retained，不触发设备暂停。
3. 按合同迁移启动占位及私有 smoke hook；借用探针与正式提交使用同一个 `LaidOutFrame`。保留正式旧入口，记录历史安装消费证据和后继退役条件。
4. RR-F135 复用既有 `FaultSlot` 的 allocation/capacity Reason：仅实际分配失败导致观测桥操作未完成时报 `host.rpa.allocation_failed`，真实预算/容量拒绝保留 `host.rpa.capacity_exceeded`。逐入口区分操作失败与纯观测丢失；后者标 Unknown/不完整、允许 Gameplay 继续，前者如实保留失败阶段和实际副作用，不能虚报 submit/present 完成。`catch-all` 不得一律转成 `bad_alloc` 或 allocation_failed。检查故障槽到错误交付的完整路径在持续 OOM 下不再分配，预建 owning `core::Error` 的复制也须检验，不能预设安全。

上述步骤逐个落到[实际接线](../contracts/render-player-writer.md#提交资源与交付)：`presentation_materializer.cpp` 用 T-05 私有 helper 将最终 Pout 写入 camera.projectionMatrix；`session_worker_owner.cpp` 在原 reservation 内移动构造 variant 分支，`frame_observation.hpp` 统一 snapshot/layout view，`frame_delivery.cpp` 同步 payloadBytes/frameByteBound，`execution_host_frame.cpp::OverlayRenderer` 增 `submitLaidOut(frame,currentTarget)` 并转发同一个 binding。scene 在最终 gate 之前建好；`presentOwnedFrame` 按分支传完整 target，旧 adapter 用模板能力检测保持可编译。`snapshot_scene.cpp` 的 FPS 沿完整投影视图逆矩阵，窗口文字不随谱旋转。写域含以上 TU 及相应非安装测试；所有固定/动态计量只计当前 variant 的一份拥有值。

补充 RR-F427/F428：候选 detach（含析构、move-assign 入站）遵守既有 owner 规则，与 activate/discard 的拒绝策略一致；真实 GL rebuild 在 window/context 不可用时返回既有失败，不置恢复成功。RR-F421 区分 owner 线程首次能力初始化与已初始化缓存查询，不能把非主线程查询笼统写为全零。RR-F415 先核对内部 `mutationEpoch` 副本的全部读者；仅清理确认无用途的观察副本，保留 revision clock、借用失效及发布机制，未证实的删除留残余。

RR-F207 按[ResourceScope 实现去重](../contracts/render-player-writer.md#resourcescope-实现去重f207)覆盖全部五类加载与 fallback 分支。额外写域限 `engine/assets/src/resource_scope.cpp` 的私有共用实现及 `tests/assets/{resource_manager_tests.cpp,CMakeLists.txt}`；公共 ResourceScope/Lease/Handle 定义与 manager 策略保持。先固定五类与混合依赖的卡前结果，再以 TU 内 typed helper 合并加载/登记和 fallback 流程，保留原索引、回滚边界和诊断；不是新增资源缓存、所有权框架或全面资源系统改造。
