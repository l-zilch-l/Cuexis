## 目标

`DOC`；生成可复现的派单输入，核对设计基线与实施工作树的差异。采用规则见[计划](../plan.md#唯一派单授权入口)。

## 输入

[可实施性索引](../design-readiness.md)、[调度](../schedule.md)、[基线记录](../findings.md#13-可实施性审查处置2026-11-21)、[验收](../acceptance.md#交叉验证)。

## 写域

本卡证据目录和派单清单。基线登记差异交集成者回写 findings，调度反例在临时副本运行。

## 步骤

1. 从仓库根运行 `git rev-parse HEAD`、`git rev-parse 'HEAD^{tree}'`、`git status --short` 和 `git diff --name-status 9623efa3 --`。对当前受影响项保留 `git diff --binary 9623efa3 -- <列出的路径>`。用 `git ls-files --others --exclude-standard -- docs/stage_plans/active/stage-07-rr` 列额外设计输入，并以 `Get-FileHash -Algorithm SHA256 -LiteralPath <路径>` 绑定派单包内各未提交文件。以任务 ID 列出合同、CMake/安装、源码、schema、fixture、复跑命令和回滚基线。旧报告证据保留原 SHA，当前变化的对象单列重取证。
2. 从本轮设计基线或已登记采用记录绑定合同 revision、任务 scope 与阶段。每次派单按验收页交付卡片、链接输入、该卡的基线和命令。独立回执需标卡内首改路径、测试目标、正反结果与触发的停止条件。

## 任务级验收

- `python -B tools/verification/check_plan_schedule.py` 和 `python -B tools/verification/test_check_plan_schedule.py` 退出 0。复制阶段目录到本卡证据目录的独立临时子目录，先用 `python -B tools/verification/check_plan_schedule.py --stage-dir <副本路径>` 确认退出 0；仅在副本中把 T-05 的前置加上 T-06，再运行同一命令，应退出 1。唯一错误须精确对应 T-05 行的 `prerequisite T-06 must be in an earlier wave`。保存前后哈希、命令、stdout/stderr、退出码、单行差异和回执，确认正本 schedule.md 哈希未变、副本其他文件未变。
- `python -B tools/check_docs.py` 与 `git diff --check` 退出 0。抽查派单清单中的合同哈希和输入路径可重现，冷启动回执覆盖[阶段验收](../acceptance.md#交叉验证)指定的卡。发现不存在的入口、未给定的合同选择或无法说明预期诊断时，该卡回到设计复核。
