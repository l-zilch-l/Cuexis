## 目标

`R1`；把默认与显式候选构建的实现闭包分开，保留规则、输入格式和消费合同。采用见[计划](../plan.md#唯一派单授权入口)。

## 输入

[R1 源表](../contracts/runtime-timing.md#r1八个-playback-tu)、[构建与安装表](../contracts/runtime-timing.md#构建头与安装)、[D-18](../architecture-design.md#d-18-按用途编译-player)、[构建指南](../../../../guides/BUILDING.md)。首改入口为 [Playback CMake](../../../../../engine/playback/CMakeLists.txt)、[准备编排](../../../../../engine/playback/src/playback_session_prepare.cpp)、[准备阶段实现](../../../../../engine/playback/src/playback_session_prepare_stages.cpp)和 [CXC CMake](../../../../../engine/cxc/CMakeLists.txt)。

## 写域

根 `CMakeLists.txt` 的 `CUEXIS_ACTIVE_TARGETS`、依赖 `ALLOWED` 和实验 static 安装归档、`engine/playback/CMakeLists.txt` 与合同点名 TU（含 `playback_session_prepare_stages.cpp` 和 `playback_session_prepare_internal.hpp`）、`engine/cxc/CMakeLists.txt` 与 `cxc_candidate.cpp` 源归属、`app/player/CMakeLists.txt`、`tools/{cxc/cxc_common,chart/chart_candidate}/CMakeLists.txt`、`tests/{cxc,playback}/CMakeLists.txt` 和对应 fixture，以及本卡新增的 `cmake/VerifyRrPlaybackIsolation.cmake`。按实际目标图同步构建与依赖合同。冻结已装声明、布局、默认安装合同、作者类型及 Packed wire。

## 步骤

1. 按 R1 源表分离候选接线。`playback_session_prepare.cpp` 的 candidate 分支继续经 prepare hook 进入。在实验源表为 `prepareCandidateStage` 提供唯一实现，从普通 `playback_session_prepare_stages.cpp` 搬走候选 lowering 和资源能力填表，默认源表只提供同签名拒绝 hook，返回 `playback.candidate.disabled` 且不产生准备结果。对文件、内存与工程的显式候选选择保留原拒绝。普通 `loadDocumentStage`、合同校验与提交顺序留在共享路径。
2. 将 `engine/cxc/src/cxc_candidate.cpp` 的扩展解析和选中/整包候选条目验证编入独立内部 static `cuexis_cxc_candidate`。候选 Playback 与显式开发工具消费该目标，CXC 扩展测试在该目标存在时链接。通用 `cuexis_cxc` 保持 CXC v1 整包校验、路径、内容及资源完整性，依赖方向为候选目标指向 CXC。开发工具仍在通用校验之外调用同一份候选验证实现。只在实验 static SDK 中随 Playback 导出所需私有归档，照旧保持构建侧头与安装头边界。
3. 同步条件源表、依赖 `ALLOWED`、安装与测试注册。普通、实验和开发工具分别记录构建闭包。R1 保留现行 Chart 基础工具链和已装内部归档的兼容要求，检查的是从 Playback/Player 可达的候选接线与 CXC 解码目标。新运行内核及作者编译目标按后继任务的源头创建顺序引入。

## 任务级验收

执行采用后的定向门禁，保存两类目标的实际编译源、依赖及失败输出。

1. 对 `headless-debug`、`debug`、`candidate-headless-debug`、`candidate-shared-debug`，先在 `out/build/<preset>/.cmake/api/v1/query/` 放置空文件 `codemodel-v2`，再执行 `cmake --preset <preset> --fresh` 和 `cmake --build --preset <preset> --target cuexis_playback cuexis_playback_tests cuexis_cxc_tests`。在 `debug`、`candidate-shared-debug` 追加 `cmake --build --preset <preset> --target cuexis_player`。在根 `CMakeLists.txt` 新增 `cuexis_rr_playback_isolation` 注册，调用本卡新增的 `cmake/VerifyRrPlaybackIsolation.cmake`，传入当前 binary dir、候选开关与 Player 是否存在。该脚本读取此配置的 File API codemodel，从 Playback 和存在时的 Player 递归检查源及链接闭包；缺 codemodel 或目标时失败。用 `ctest --test-dir out/build/<preset> --no-tests=error -R '^(cuexis_rr_playback_isolation|cuexis_architecture_tests)$'` 执行。
2. 默认闭包排除候选源表、候选 `prepareCandidateStage` 定义、`cxc_candidate.cpp`、`cuexis_cxc_candidate` 和候选 Judgement/作者/成品边。实验闭包含已列候选实现且每个 hook 只有一个定义。隔离副本分别将 `playback_session_gameplay.cpp`、候选 prepare 实现放回默认源表，或向默认 `cuexis_cxc` 加入 `cxc_candidate.cpp`，闭包门禁要指出具体来源。对照的构建配置须能生成可读 codemodel，不能以其他配置错误代替拒绝。
3. 在 `tests/playback/` 注册 `rr_r1_playback_sources`，在 `tests/cxc/` 注册 `rr_r1_cxc_package_integrity`，四个配置均用 `ctest --test-dir out/build/<preset> --no-tests=error -R '^(rr_r1_playback_sources|rr_r1_cxc_package_integrity)$'`。普通入口加载原 CXC v1 通过，整包损坏或资源闭包缺项沿用原诊断且不提交。默认显式候选选择和默认 prepare 候选分支报 `playback.candidate.disabled`；实验静态 Packed 与 Behavior 源条目通过，候选 metadata/编译失败保留原诊断。另用 `ctest --test-dir out/build/debug --no-tests=error -R '^cuexis_cxc_tools$'` 验证独立工具装配，先构建 `cuexis_cxc_pack`、`cuexis_cxc_validate`、`cuexis_cxc_unpack`。
4. 在 `candidate-headless-debug` 先执行 `cmake --build --preset candidate-headless-debug --target cuexis_playback cuexis_gameplay cuexis_playback_tests cuexis_chart_candidate`；在 `candidate-shared-debug` 先执行 `cmake --build --preset candidate-shared-debug --target cuexis_playback cuexis_audio_sdl cuexis_playback_tests cuexis_chart_candidate`。按根 `CUEXIS_STATIC_IMPLEMENTATION_TARGETS` 清单核对 static 安装归档均已生成，包含不由 Playback 链接触达的 `cuexis_gameplay`；新增私有归档随 Playback 的实际依赖构建。然后用 `ctest --test-dir out/build/<preset> --no-tests=error -R '^cuexis_gameplay_installed_consumer$'` 取证。安装用例内的 typed fixture、候选工具及独立宿主运行均须有输出。

## 证据

`out/review/stage-07-rr/T-04/` 保存 codemodel、`ALLOWED` 差异、普通与实验装载轨迹、工具和安装消费者日志、三个闭包阴性对照。

## 停止条件

默认闭包仍能到达任一候选接线或 CXC 候选解码，或者普通整包校验、既有诊断、安装消费或公开类对照失败时停止该批，恢复原装配。若必须改规则或引入新时间、玩法或 wire，按计划登记越界。
