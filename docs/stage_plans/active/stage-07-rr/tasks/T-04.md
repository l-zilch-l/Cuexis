## 目标

`R1`；把默认与显式候选构建的实现闭包分开，保留规则、输入格式和消费合同。采用见[计划](../plan.md#唯一派单授权入口)。

## 输入

[R1 源表](../contracts/runtime-timing.md#r1八个-playback-tu)、[构建与安装表](../contracts/runtime-timing.md#构建头与安装)、[D-18](../architecture-design.md#d-18-按用途编译-player)、[构建指南](../../../../guides/BUILDING.md)。首改入口为 [Playback CMake](../../../../../engine/playback/CMakeLists.txt)、[准备编排](../../../../../engine/playback/src/playback_session_prepare.cpp)、[准备阶段实现](../../../../../engine/playback/src/playback_session_prepare_stages.cpp)和 [CXC CMake](../../../../../engine/cxc/CMakeLists.txt)。

## 写域

根 `CMakeLists.txt` 的 `CUEXIS_ACTIVE_TARGETS`、依赖 `ALLOWED` 和实验 static 安装归档、`engine/playback/CMakeLists.txt` 与合同点名 TU（含 `playback_session_prepare_stages.cpp` 和 `playback_session_prepare_internal.hpp`）、`engine/cxc/CMakeLists.txt` 与 `cxc_candidate.cpp` 源归属、`app/player/CMakeLists.txt`、`tools/{cxc/cxc_common,chart/chart_candidate}/CMakeLists.txt`、`tests/{cxc,playback}/CMakeLists.txt` 和对应 fixture，以及本卡新增的 `cmake/VerifyPlaybackCandidateIsolation.cmake`。按实际目标图同步构建与依赖合同。冻结已装声明、布局、默认安装合同、作者类型及 Packed wire。

补充写域为根 `CMakeLists.txt` 的库类型初始化/observer 检查顺序、`cmake/CuexisLibraryType.cmake` 的对应配置、`tests/CMakeLists.txt`、`tests/shader/{CMakeLists.txt,shader_cache_tests.cpp}` 及已有 Playback 摘要测试。按实际依赖同步本卡触及目标的具名 `ALLOWED`（RR-F220），不扩大为全仓依赖治理。

## 步骤

1. 按 R1 源表分离候选接线。`playback_session_prepare.cpp` 的 candidate 分支继续经 prepare hook 进入。在实验源表为 `prepareCandidateStage` 提供唯一实现，从普通 `playback_session_prepare_stages.cpp` 搬走候选 lowering 和资源能力填表，默认源表只提供同签名拒绝 hook，返回 `playback.candidate.disabled` 且不产生准备结果。对文件、内存与工程的显式候选选择保留原拒绝。普通 `loadDocumentStage`、合同校验与提交顺序留在共享路径。两个候选 hook 源文件的进一步独立拆分需要调整内部头或公共头边界，本卡保持现状并登记，移交 T-08 与 RR-F122 同批处理。
2. 将 `engine/cxc/src/cxc_candidate.cpp` 的扩展解析和选中/整包候选条目验证编入独立内部 static `cuexis_cxc_candidate`。候选 Playback 与显式开发工具消费该目标，CXC 扩展测试在该目标存在时链接。通用 `cuexis_cxc` 保持 CXC v1 整包校验、路径、内容及资源完整性，依赖方向为候选目标指向 CXC。开发工具仍在通用校验之外调用同一份候选验证实现。只在实验 static SDK 中随 Playback 导出所需私有归档，照旧保持构建侧头与安装头边界。
3. 同步条件源表、依赖 `ALLOWED`、安装与测试注册。普通、实验和开发工具分别记录构建闭包。R1 与本卡 F302 同步保留工具和已装消费行为，检查默认 Playback/Player 的 Chart 源、头、链接闭包，并独立检查工具与测试闭包。新运行内核及作者编译目标按后继任务的源头创建顺序引入。

4. RR-F216 将库类型初始化放在 observer 准入检查之前，保持 Windows/STATIC 准入规则。RR-F217 以 `cuexis_shader_cache` 是否存在接入 cache 测试，现有 `cuexis_shader_tests` 按目标条件选择 compiler/cache 源及链接；GL 开启、shader tools 关闭时也须测试 cache，不为启测拉入 shaderc。RR-F434 在现有 Playback 测试补内部定版本摘要对不支持版本的拒绝，保留历史算法和公共默认版本。

RR-F302 按[Chart 源表与安装隔离](../contracts/runtime-timing.md#chart-源表与安装隔离rr-f302)完整实施：保留基础 `cuexis_chart`，在原 Chart CMake 内创建 `cuexis_chart_codec` / `cuexis::chart_codec` / `InternalChartCodec` 与 `cuexis_chart_tools` / `cuexis::chart_tools` / `InternalChartTools`。`cuexis_chart_candidate` 保留已有工具可执行身份。按合同逐文件搬源/头，提取 `packed_chart_tables_common.cpp`、`packed_chart_read.cpp`，Writer 留 tools；基础 `chart_writer.cpp` 保留。同步 Playback 私有 candidate 类型及调用条件，默认目标无候选 include 根。源编译 lowering/Behavior 属 tools，纯 Reader 的 codec 无作者编译实现。

F302 追加实施写域：`engine/chart/CMakeLists.txt`、合同列明源与 build-only 头及新 codec/tools include 根；`engine/CMakeLists.txt`、`engine/gameplay_packed/CMakeLists.txt` 的目标创建条件；`engine/playback/src/{playback_source_state,playback_candidate_internal,playback_session_internal,playback_session_prepare_internal}.hpp` 和引用候选状态的既有 TU；根 active/ALLOWED/static 安装清单、`cmake/VerifyPlaybackCandidateIsolation.cmake` 与现有安装消费者脚本；`tools/{chart,cxc,gameplay}`、`tests/{chart,cxc,playback,runtime,gameplay_packed,asset_publish}` 的具名消费者 CMake/include 接线和原测试。共享头拆分同步直接调用方，不复制 codec。保留默认 static `InternalChart`、`InternalJudgement` 创建/安装，实验安装按实际闭包加新归档；完整判据见下列 F302 验收。

## 任务级验收

执行采用后的定向门禁，保存两类目标的实际编译源、依赖及失败输出。

1. 对 `headless-debug`、`debug`、`candidate-headless-debug`、`candidate-shared-debug`，先在 `out/build/<preset>/.cmake/api/v1/query/` 放置空文件 `codemodel-v2`，再执行 `cmake --preset <preset> --fresh` 和 `cmake --build --preset <preset> --target cuexis_playback cuexis_playback_tests cuexis_cxc_tests`。在 `debug`、`candidate-shared-debug` 追加 `cmake --build --preset <preset> --target cuexis_player`。在根 `CMakeLists.txt` 新增 `cuexis_rr_playback_isolation` 注册，调用本卡新增的 `cmake/VerifyPlaybackCandidateIsolation.cmake`，传入当前 binary dir、候选开关与 Player 是否存在。该脚本读取此配置的 File API codemodel，从 Playback 和存在时的 Player 递归检查源及链接闭包；缺 codemodel 或目标时失败。用 `ctest --test-dir out/build/<preset> --no-tests=error -R '^(cuexis_rr_playback_isolation|cuexis_architecture_tests)$'` 执行。
2. 默认闭包排除候选源表、候选 `prepareCandidateStage` 定义、`cxc_candidate.cpp`、`cuexis_cxc_candidate` 和候选 Judgement/作者/成品边。实验闭包含已列候选实现且每个 hook 只有一个定义。隔离副本分别将 `playback_session_gameplay.cpp`、候选 prepare 实现放回默认源表，或向默认 `cuexis_cxc` 加入 `cxc_candidate.cpp`，闭包门禁要指出具体来源。对照的构建配置须能生成可读 codemodel，不能以其他配置错误代替拒绝。
3. 在 `tests/playback/` 注册 `rr_r1_playback_sources`，在 `tests/cxc/` 注册 `rr_r1_cxc_package_integrity`，四个配置均用 `ctest --test-dir out/build/<preset> --no-tests=error -R '^(rr_r1_playback_sources|rr_r1_cxc_package_integrity)$'`。普通入口加载原 CXC v1 通过，整包损坏或资源闭包缺项沿用原诊断且不提交。默认显式候选选择和默认 prepare 候选分支报 `playback.candidate.disabled`；实验静态 Packed 与 Behavior 源条目通过，候选 metadata/编译失败保留原诊断。另用 `ctest --test-dir out/build/debug --no-tests=error -R '^cuexis_cxc_tools$'` 验证独立工具装配，先构建 `cuexis_cxc_pack`、`cuexis_cxc_validate`、`cuexis_cxc_unpack`。
4. 在 `candidate-headless-debug` 先执行 `cmake --build --preset candidate-headless-debug --target cuexis_playback cuexis_gameplay_packed cuexis_playback_tests cuexis_chart_candidate`；在 `candidate-shared-debug` 先执行 `cmake --build --preset candidate-shared-debug --target cuexis_playback cuexis_audio_sdl cuexis_playback_tests cuexis_chart_candidate`。按根 `CUEXIS_STATIC_IMPLEMENTATION_TARGETS` 清单核对 static 安装归档均已生成，包含不由 Playback 链接触达的 `cuexis_gameplay_packed`（`cuexis_gameplay` 是 INTERFACE 目标，没有可构建产物）；新增私有归档随 Playback 的实际依赖构建。然后用 `ctest --test-dir out/build/<preset> --no-tests=error -R '^cuexis_gameplay_installed_consumer$'` 取证。安装用例内的 typed fixture、候选工具及独立宿主运行均须有输出。

- 承接追踪：RR-F301 由本卡的四配置源/链接闭包与默认源表阴性用例覆盖，不另增结构任务；RR-F208（候选 lowering 与能力填表搬入实验源表后，预检与预算顺序仍在共享路径）在 `rr_r1_playback_sources` 的源表断言里核对顺序。RR-F214（`tests/playback/CMakeLists.txt` 重复编译库文件）确认重复源被移除，同时覆盖 RR-F121 归入本卡的测试重复编译部分；RR-F121 的文档主句不在本卡重开。

- RR-F216 在全新无缓存 Windows 配置中启用 observer、不显式传库类型，默认 STATIC 配置通过；显式 SHARED 及非 Windows 仍拒绝，旧缓存通过不能代验。RR-F217 在 GL ON/tools OFF 下构建现有 shader 测试目标，列出并运行 cache 用例，确认无 compiler 源/shaderc 边；tools ON 保留 compiler/cache 对照。均先用同配置 `ctest --test-dir out/build/<preset> --no-tests=error -N -R '<已核对的用例表达式>'` 核对非零注册，再去掉 `-N` 执行；记录实际配置及匹配用例，不另建框架。RR-F434 在已有 Playback 摘要用例验证不支持版本拒绝且默认/历史合法版本结果不变。

**RR-F302 完整验收（实施时执行）。** 在以上四配置的同一 File API 检查中加入基础 Chart/codec/tools 源表与 include 根，不能只检查最终 binary 符号；每个 TU 唯一归属。默认 Playback/Player 无 codec/tools/cxc_candidate，旧 Chart/CXT1 正反例和 v4 resolver/Writer 仍通过。候选、工具和测试按其消费合同取得正确源组，codec 无 CXT2/lowering/Behavior 编译或 Writer TU，缺 codemodel/目标/预期源即失败。

1. 追加两个独立配置目录，从 `headless-debug` 配置且覆盖 `-DCUEXIS_ENABLE_CHART_V5_CANDIDATE=OFF -DBUILD_TESTING=OFF -DCUEXIS_BUILD_TESTS=OFF`：`out/build/rr-f302-minimal` 再设 `-DCUEXIS_BUILD_DEVELOPER_TOOLS=OFF`，`out/build/rr-f302-tools` 再设 `-DCUEXIS_BUILD_DEVELOPER_TOOLS=ON`。均在各自目录预放 File API query，再用 `cmake --preset headless-debug -B <dir> --fresh <上述覆盖>`；其后用 `cmake --build <dir>` 指定目标，不误用原 preset binary dir。minimal 应无 codec/tools/cxc_candidate/旧 gameplay_packed，但必须有 chart/judgement；tools 应有完整工具支持库，默认 Playback 闭包仍与 minimal 一致。测试关闭时直接以 `cmake -DCUEXIS_BINARY_DIR=<dir> -DCUEXIS_ENABLE_CHART_V5_CANDIDATE=OFF -DCUEXIS_BUILD_DEVELOPER_TOOLS=<ON或OFF> -DCUEXIS_BUILD_TESTS=OFF -P cmake/VerifyPlaybackCandidateIsolation.cmake` 核对；本卡为脚本实现这些参数，不能把缺 CTest 注册当通过。
2. 保留 `cuexis_chart_tests` 和原用例注册，给它显式链接 codec/tools。在四个启测配置构建该目标及 `cuexis_cxc_tests`、`cuexis_runtime_tests`、`cuexis_playback_tests`；本卡在已有 Chart 测试内注册 `rr_f302_chart_boundaries`，覆盖旧 Reader/CXT1/v4 Resolver、Packed read/write golden 与诊断、CXT2/candidate assembly、migration 对照。先以 `ctest --test-dir out/build/<preset> --no-tests=error -N -R '^rr_f302_chart_boundaries$'` 确认非零，再去掉 `-N` 执行；这些旧工具能力在 candidate=OFF 也须通过。原容量探针只核对可构建及链接闭包，不在本卡运行性能探针。
3. `debug` 的 developer tools 开启时，构建 `cuexis_chart_candidate cuexis_chart_validator cuexis_chart_migrator cuexis_cxc_pack cuexis_cxc_validate cuexis_cxc_unpack`，实际执行既有 `cuexis_candidate_cli`、`cuexis_chart_tool_tests`、`cuexis_cxc_tools`（逐个先 `-N --no-tests=error` 核注册）；保留默认已有成功产物、非法 Packed/CXT 的诊断和退出分类。`rr-f302-tools` 在测试关闭时也必须构建这六个可执行目标，工具本身不依赖测试目标才能链接。
4. 在同一隔离脚本内生成独立编译/链接 probe：仅链基础 Chart 可读旧谱，包含 codec/tools 头各自编译失败；仅链 codec 可 decode 固定合法 Packed 并比较原 identity，但包含 `cxt_v2_loader.hpp`/`candidate_lowering.hpp`/`packed_chart_writer.hpp` 失败；再分别手写等签名声明并实际调用 `lowerCandidateRuntime`、`packed::encode`，链接必须失败。链 tools 的对照须成功；所有阴性记录实际 include/未解析符号，不能以 fixture/CMake 错误代验。基础旧 Chart 编译/Writer 符号因兼容用途保留，不列入这些链接阴性。
5. 结构阴性在可配置的隔离副本分别把 `cxt_v2_loader.cpp` 放回基础源表、给基础 Chart 加 codec 链接、向基础 PUBLIC include 加 tools 根，门禁均指出来源并失败。与 R1 原三个阴性共用脚本，不新建门禁框架。
6. 默认 static（含 minimal）、实验 static 与实验 shared 各安装至独立 prefix。先依据该配置安装清单构建所有归档，点名 `cuexis_chart`、`cuexis_judgement`（T-12 后含 timing），再安装；默认 prefix 保留 `Cuexis::InternalChart`/`Cuexis::InternalJudgement` 且无新 codec/tools export，实验 static 必须包含实际闭包的 `InternalChartCodec`/`InternalChartTools`。用原 `VerifyExternalConsumer.cmake`/`VerifyGameplayInstalledConsumer.cmake` 支持的独立消费者接线确认导出 target 完整、无构建树绝对路径、公共消费可链接运行；minimal 无测试注册时由本卡脚本调用同一安装/消费流程。shared 检查新增内部归档/头不进入安装包。默认 tools=ON/测试=ON 仍不得把作者归档泄入默认 SDK。
