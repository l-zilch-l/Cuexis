## 步骤

拆旧作者、图、timebase 与旧回放适配到 `cuexis_judgement_compile`，直接 PUBLIC 链 `cuexis::judgement`、`cuexis::core`。按合同同卡更新旧 Packed、作者工具、judgement 测试链接及私有 include、根依赖 `ALLOWED`、分区门禁和实验 static SDK 安装/export。默认顶层 `BUILD_TESTING=ON` 并启用 `CUEXIS_BUILD_TESTS` 时也须创建 `judgement_compile`，无须启用候选 Reader 或开发工具。RPA 的 B3 夹具直接包含作者头并调用旧 `prepareResolvedGameplay`；在 `tests/rpa/CMakeLists.txt` 为 `cuexis_rpa_tests` 追加 `PRIVATE cuexis::judgement_compile`，在根 CMake 的该测试 `ALLOWED` 追加同一项。不经 Playback/Packed 转交作者头，不因启测增加默认安装件。本卡仍扫描整个运行 `include/internal/src`，不引入 `engine/timing`、`beat_us_compile`、T-12 共享产物头或新成品 target。

迁移执行态与 Prepared storage；定义运行侧 `normalized_score.hpp/.cpp`、表/单元、局部 release 域、基数复算、整数 Fold 与 Playback DTO/摘要投影，以纯 tick records 验证。接 `(sessionScope,runEpoch)`、容量预检、每 tick/control seal 与 fault 前缀；保存 v3 同局接收编号和完整 normalized Fold，旧 codec 拒绝所有 v3 历史。`advanceStopCut` 复用每 tick 事务；真实异步 `tryStart`、Pause drain、Resume seal 的回复及接收序锁定接线在 T-14 验证。按合同表列 T-10 buffer 方法和 facade 的实验 shared 精确导出；RR-4 旧转发保留。

本卡先创建运行 `prepared_identity.hpp` 的四个完整身份声明，以及 `phase_types.hpp` 中原样的 `StableDeclarationId`；`prepared_gameplay_records.hpp` 直接包含两头，旧作者头转引唯一完整定义，`SessionConfiguration` 保留按值身份。迁移顺序先值类型、再运行 records/storage、最后作者/图拆出，禁止用前置声明或私有 include 满足运行消费者。本卡同时在作者工具 CMake 首创 `cuexis_gameplay_author_cli`/`cuexis::gameplay_author_cli`：按合同转移现有 CLI 源、metadata helper、include 和依赖，切换 `cuexis_gameplay_assemble` 及 `cuexis_chart_candidate` 的 candidate 链接，更新根 active-target/ALLOWED。`cuexis_gameplay_author` 保留纯作者源；T-13 只在此基础追加 Source target 和新分支。

在 `execution_kernel_submit.cpp`/`session.cpp` 与仓内 `canonical_ingress.hpp` 实现合同的 `receiveCanonicalBatch`；kernel 的同局游标是唯一 producer，接收编号在 late/admission 前分配，带编号的接受或拒绝记录与游标一起提交。`stop_cut.hpp` 的 `acceptedIngressThrough(session, run)` 直接读该状态，`advanceStopCut` 验上界一致再关闭接收。Resume trace 共用编号分配器并随真实控制 seal 提交。T-14 才把 scheduler/Playback Stop 的生产调用接入；本卡纯 tick fixture 用这些真实入口生成前缀，不手填 `acceptedThrough` 或修改私有计数。

## 任务级验收

实施时新增、当前未执行：`ctest --preset candidate-debug --no-tests=error -R '^cuexis_rr_advance_contract$'` 用纯 tick records 跑 [GP-02…05、CLK-02](../contracts/runtime-timing.md#验收向量与任务前置)，核对 Exact 与真实 release、单元失败/竞争折叠、精确比例与终局摘要、容量/故障、Stop 内存回放。另跑原 judgement 恢复、成品 codec 及作者工具 fixture。先 `cmake --build --preset candidate-headless-debug --target cuexis_judgement_tests cuexis_gameplay_packed_tests cuexis_gameplay_assemble cuexis_playback_tests cuexis_chart_candidate`，按 T-04 的安装目标闭包构建归档，再跑 `ctest --preset candidate-headless-debug --no-tests=error -R '^(cuexis_architecture_tests|cuexis_gameplay_installed_consumer)$'`。文件 API/实际命令证明这批无 timing/new Reader。独立构建 `cmake -S tests/consumers/judgement-runtime -B out/rr-judgement-runtime` 与 `cmake --build out/rr-judgement-runtime` 只暴露 Core/Judgement；加入旧作者 `timebase.hpp`、`cuexis/timing/timing_map.hpp` 的两个阴性各须因头不可见失败。

纯运行正向必须自行构造四个身份声明及 `StableDeclarationId`，填一份合法 `CompiledGameplayView` 并成功 prepare，源值销毁后仍能读取 prepared 身份/records；只做空 `#include` 不通过验收。分别直接包含每个新值头验证自包含，include trace 不得到 `gameplay_assembler*`、`gameplay_graph*`、编译根或内部 context。CLI 定向构建两可执行程序后跑既有 `cuexis_gameplay_assembler_cli`，核对新静态 target 的真实源/边、author 无 Playback/CXC 边，以及 tools OFF 时不创建 CLI；`beat-us` 不属于本卡验收。

在 `headless-debug`（candidate OFF、developer tools OFF）与 `candidate-headless-debug` 两个启测配置分别执行下列三条命令，`<preset>` 取该配置名。检查缓存 `BUILD_TESTING=ON`、`CUEXIS_BUILD_TESTS=ON`，以实际构建与 B3 结果证明旧作者夹具可见、可链接和可运行。

```text
cmake --preset <preset>
cmake --build --preset <preset> --target cuexis_rpa_tests
ctest --test-dir out/build/<preset> --no-tests=error -R "^B3 different original Ticks forwarded to one dispatch retain canonical occurrence order$"
```

GP-02 短 Hold 必须通过 prepare：body 与唯一 Body 窗均 `[850,851)`、Body target `851`，Tail target `1000` 且尾窗不变；`press@850 → advance(854) → release observation 849` 路由至 tick 852，得 `Tail Miss/break/Early/−151`。CLK-02 验接受前缀内序号 6/tick 105 保留原编号并可 replay，但 Stop@100 不结算；序号 7/tick 90 与 `Miss@100` 各结算一次，锁后到达的 tick 95 不获编号、不入归档、不结算。

CLK-02 的 0–5 先由同一接收入口提交合法且不匹配义务的输入，之后各批实际生成 6/7；查询取得上界 7，再构造 StopCut。这是内核可接收未来 tick 的受控用例，不经实时 capture 伪造未来时钟证明。另覆盖合法空前缀、首个序号 0、late 拒绝仍增加上界、无效 canonical/批次重投/预留失败不增加、Resume trace 首次 seal 增加而重投不增加，恢复后下一编号连续。真实 capture 的可构造对照由 T-14 承接。

实验 shared 同跑 `cuexis_gameplay_installed_consumer` 与 `cuexis_shared_export_surface`，独立消费者从 facade 构造 buffer，移动构造/赋值，读取 `at/dictionary` 后析构；默认库保持 R5 的帧布局导出基线，不增加本卡 Gameplay 符号。缺 `CUEXIS_PLAYBACK_API` 的阴性必须在符号检查或消费者链接失败。
