## 任务级验收

实施时新增、当前未执行：`ctest --preset candidate-debug --no-tests=error -R '^cuexis_rr_advance_contract$'` 用纯 tick records 跑 [GP-02…05、CLK-02](../contracts/runtime-timing.md#验收向量与任务前置)，核对 Exact 与真实 release、单元失败/竞争折叠、精确比例与终局摘要、容量/故障、Stop 内存回放。另跑原 judgement 恢复、成品 codec 及作者工具 fixture。先 `cmake --build --preset candidate-headless-debug --target cuexis_judgement_tests cuexis_gameplay_packed_tests cuexis_gameplay_assemble cuexis_playback_tests cuexis_chart_candidate`，按 T-04 的安装目标闭包构建归档，再跑 `ctest --preset candidate-headless-debug --no-tests=error -R '^(cuexis_architecture_tests|cuexis_gameplay_installed_consumer)$'`。文件 API/实际命令证明这批无 timing/new Reader。独立构建 `cmake -S tests/consumers/judgement-runtime -B out/rr-judgement-runtime` 与 `cmake --build out/rr-judgement-runtime` 只暴露 Core/Judgement；加入旧作者 `timebase.hpp`、`cuexis/timing/timing_map.hpp` 的两个阴性各须因头不可见失败。

在 `headless-debug`（candidate OFF、developer tools OFF）与 `candidate-headless-debug` 两个启测配置分别执行下列三条命令，`<preset>` 取该配置名。检查缓存 `BUILD_TESTING=ON`、`CUEXIS_BUILD_TESTS=ON`，以实际构建与 B3 结果证明旧作者夹具可见、可链接和可运行。

```text
cmake --preset <preset>
cmake --build --preset <preset> --target cuexis_rpa_tests
ctest --test-dir out/build/<preset> --no-tests=error -R "^B3 different original Ticks forwarded to one dispatch retain canonical occurrence order$"
```

GP-02 短 Hold 必须通过 prepare：body 与唯一 Body 窗均 `[850,851)`、Body target `851`，Tail target `1000` 且尾窗不变；`press@850 → advance(854) → release observation 849` 路由至 tick 852，得 `Tail Miss/break/Early/−151`。CLK-02 验接受前缀内序号 6/tick 105 保留原编号并可 replay，但 Stop@100 不结算；序号 7/tick 90 与 `Miss@100` 各结算一次，锁后到达的 tick 95 不获编号、不入归档、不结算。

实验 shared 同跑 `cuexis_gameplay_installed_consumer` 与 `cuexis_shared_export_surface`，独立消费者从 facade 构造 buffer，移动构造/赋值，读取 `at/dictionary` 后析构；默认库保持 R5 的帧布局导出基线，不增加本卡 Gameplay 符号。缺 `CUEXIS_PLAYBACK_API` 的阴性必须在符号检查或消费者链接失败。
