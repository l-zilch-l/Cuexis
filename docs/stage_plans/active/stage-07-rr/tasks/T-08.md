## 目标

`RR4`；核对和迁移候选 SDK 安装面，保持过渡期消费者与基线兼容。采用见[计划](../plan.md#唯一派单授权入口)。

## 输入

[安装与窗口](../contracts/runtime-timing.md#安装与窗口)、[RR-4 逐符号兼容迁移](../contracts/runtime-timing.md#rr-4-逐符号兼容迁移)、[D-24](../architecture-design.md#d-24-sdk-判定接入与实验扩展)、[构建指南](../../../../guides/BUILDING.md)。首改入口为 [Playback CMake](../../../../../engine/playback/CMakeLists.txt)、[shared 导出检查](../../../../../cmake/VerifySharedExports.cmake)和[安装消费者](../../../../../tests/external/gameplay_consumer.cpp)。

## 写域

Playback 逐符号表列出的 `include/cuexis/playback/experimental/{gameplay,gameplay_realtime,gameplay_replay}.hpp` 与同版旧入口所在的 TU，包括 `playback_source_gameplay.cpp`、`playback_session_gameplay.cpp`、`playback_session_prepare_gameplay.cpp`、`playback_session_gameplay_seek.cpp`、`playback_session_realtime.cpp`、`playback_session_execution.cpp` 以及 `rg` 定位的表列其余定义。安装与门禁写域为 `engine/playback/CMakeLists.txt`、根 `CMakeLists.txt`、`cmake/{VerifySharedExports,VerifyGameplayInstalledConsumer}.cmake` 及本卡新增的 `cmake/VerifySdkFacadeCompat.cmake`。

仓内接线写域为 `engine/playback/internal/cuexis/playback/execution_host_access.hpp`、`engine/playback/src/playback_session_execution_host_access.cpp`、`playback_session.hpp` 和 `execution_control.hpp` 中 `PlaybackSession`、`PreparedPlayback`、`ExecutionFence` 的无条件 friend 声明、`app/execution_host/{CMakeLists.txt,host_candidate.cpp}`、`tests/{external,playback,rpa}/` 对应消费者、`examples/reference_host/` 及公共 API/ABI、安装与迁移说明。采用范围是现行实验内核的兼容新增和仓内接线。`materializePresentation` 另有 [R5 兼容窗口](../contracts/render-player-writer.md#兼容目标及向量)。

F313/F316 另按[应用分层与内部入口](../contracts/render-player-writer.md#应用分层与内部入口f313f316)迁移 `engine/playback/src/replay_identity.hpp` 到现有非安装 internal 根，同步 Playback/app/tests 的所有原引用，以及 `cmake/VerifyArchitecture.cmake` 的全 app include 规则。现有 ReplayIdentityAccess inline 实现、friend 和身份字节不变，不新增导出。目录与根配置的最终搬迁归 T-14；本卡先交付窄内部入口和封闭许可，不让应用继续直接包含 Playback 的 src 文件。

## 步骤

1. 逐组按表在原实现 TU 定义同版转发，为表列的每个新公开自由函数加 `CUEXIS_PLAYBACK_API`。通过候选分支的 `FILE_SET HEADERS` 随 `Cuexis::Playback` 提供实验头。安装消费者用独立实验前缀及 `-DCuexis_ALLOW_EXPERIMENTAL=ON`，沿用现有实验包准入。兼容新增保留原重载、宏成员、声明和导出。
2. 扩展 `VerifySharedExports.cmake`，在 T-06 两种 flavor 共用的 R5 精确清单之外，仅在候选分支逐项放行本卡 Gameplay 合同表内完整限定名的 `cuexis::playback::experimental` 和 `cuexis::playback::detail` 自由函数。MSVC 装饰名核对完整函数名及 `@experimental@playback@cuexis@@` 或 `@detail@playback@cuexis@@`；Itanium 核对 `6cuexis8playback12experimental` 或 `6cuexis8playback6detail` 与函数名长度边界；禁止命名空间通配。对照同配置、同工具链的卡前二进制，保留全部旧导出，实验新增与表列允许重载完全一致。默认安装头不增加；默认导出以 T-06 完成后的同配置、同工具链符号表为基线，保留其 R5 符号且无新增 Gameplay 符号。内部逐函数导出是实验 shared 的限定策略变更；build-only 头不安装、无 SDK 稳定承诺，同版本仓内消费者重编。
3. 将 owner/步骤探针移到 `tests/rpa/`。`execution_host_access.hpp` 逐函数声明 `CUEXIS_PLAYBACK_API`，由实验 `cuexis_playback` 的 `playback_session_execution_host_access.cpp` 定义并转发原成员；包括表列 `validateExecutionControlProof`、`executionAdvanceRetention`，同步 `host_candidate.cpp` 的两处消费。`execution_host_support` 保持独立 STATIC，私有包含该头。`PlaybackSession`、`PreparedPlayback`、`ExecutionFence` 无条件 friend 同一前置声明的 `detail::ExecutionHostAccess`，保持布局。RR-F122 单列仍在默认安装的 `materializePresentation` 及当前使用者，按独立 R5 窗口取证。
4. 以后获准退出协调组时，将原函数体移入同一 `cuexis_playback` TU 的 `ExecutionHostAccess` 静态成员，原限定自由函数直接转入；按原顺序校验和访问三个 friend 的私有状态。保留 build-only 入口及限定导出，再删除批准退出的旧成员和符号。不创建 Player 专用 Playback 变体。退出另行核对实际过渡发布、稳定替代、shared Player 和旧/新消费者证据；shared 验证须经过三类私有访问、控制 proof 正反例、推进决定的接受与回收水位。此步及下文退出复验只对已获准组适用；缺实际发布证据时，本轮完成分类、兼容新增、仓内迁移与消费者验证，保留旧组并记录补证条件，不预填退役版本，也不将全部工作移交 Stage 14。

5. RR-F209/F412 修正 reference host 对操作 Result/错误的实际处理，不等待从未进入的 Playback `SessionState::Failed`；保留该公开枚举，区分 Player 自身 Failed。RR-F306 的宏成员差异和 RR-F405 的默认安装泄漏只有相应旧面获准退出后才可能完整关闭；后者沿独立 R5 窗口，兼容新增不代替退役。
6. RR-F310 按[公共类型分类与兼容清理](../contracts/runtime-timing.md#公共类型分类与兼容清理f310)完成实际安装声明全集的分类与可兼容迁移，不再限于原逐符号表。RR-F210/F408 的表外类型/字段按该规则处理；F313/F316 在本卡完成 replay 内部入口与封闭 include 规则，完整应用目录/根构建方向及重复控制迁移归 T-14；两者共同按 A-08 验收。RR-F510 仅交候选能力现状及晋升所需证据，T-10/T-14 完成不自动晋升默认 SDK，新 seek 仍沿运行合同既有边界。

F310 写域限 `engine/playback/include/cuexis/playback/`、既定实验头及 `internal/cuexis/playback/` 的具名类型归属/include、对应定义和真实调用方，沿本卡已有安装/导出/消费者门禁同步；公共签名和类型身份、布局、枚举值受原窗口保护。实施先由四配置实际安装清单展开声明与签名依赖，在本卡证据目录逐项记录分类、动作和退出条件；再落实安全的内部迁移与 include 收敛，仍被旧公共面依赖的声明保留唯一完整定义。不得从零仓内引用推出删除，不以新同构 DTO 替代旧类型，不为休眠字段制造新功能。

## 任务级验收

1. 四个安装消费者配置分别用 `cmake --preset <preset> --fresh`。默认 static 用 `cmake --build --preset headless-debug --target cuexis_playback cuexis_judgement cuexis_gameplay`，默认 shared 用 `cmake --build --preset headless-shared-debug --target cuexis_playback`。候选 static 用 `cmake --build --preset candidate-headless-debug --target cuexis_playback cuexis_gameplay cuexis_chart_tests cuexis_playback_tests cuexis_chart_candidate`，候选 shared 用 `cmake --build --preset candidate-shared-debug --target cuexis_playback cuexis_audio_sdl cuexis_chart_tests cuexis_playback_tests cuexis_chart_candidate cuexis_player cuexis_host_protocol_tests cuexis_execution_host_tests`。两种候选配置的 reference-host staging 都调用 `cuexis_chart_tests` 生成输入，须先构建该目标。
2. 用 `ctest --test-dir out/build/headless-debug --no-tests=error -R '^cuexis_external_consumer_(find_package_playback|add_subdirectory_playback|find_package_core)$'`，再在实验 static/shared 两配置用 `ctest --test-dir out/build/<preset> --no-tests=error -R '^(cuexis_gameplay_installed_consumer|cuexis_reference_host_staging|cuexis_rr_sdk_facade_compat)$'`。本卡在根 CMake 注册 `cuexis_rr_sdk_facade_compat`，由 `VerifySdkFacadeCompat.cmake` 用已安装包构建 [Resume 对照](../contracts/runtime-timing.md#rr-4-逐符号兼容迁移) 的独立消费者。旧调用和新 facade 分别在独立同输入局获得相同身份、进入 Running。变更 reconciliation 的 `pauseEpoch` 后用错误身份调用必须拒绝并保持 Paused。用同一编译器从默认前缀编译实验头应报找不到头，实验前缀未 opt in 应在 `find_package` 被拒绝。
3. 默认 shared 另跑 `ctest --test-dir out/build/headless-shared-debug --no-tests=error -R '^cuexis_external_consumer_(find_package_playback|add_subdirectory_playback|find_package_core)$'`。导出差分单独使用 [T-06](T-06.md#任务级验收) 留存的两个 preset：默认侧另用 `cmake --preset shared-debug --fresh`，执行 `cmake --build --preset shared-debug --target cuexis_playback`；实验侧沿用第 1 步已配置、构建 `cuexis_playback` 的 `candidate-shared-debug`。`cuexis_shared_export_surface` 读取本树 `$<TARGET_FILE:cuexis_playback>`。分别以 `shared-debug`、`candidate-shared-debug` 替换 `<preset>` 运行 `ctest --test-dir out/build/<preset> --no-tests=error -R '^cuexis_shared_export_surface$'`，各与 T-06 同 preset、同工具链的符号表逐项比对，默认保留 R5 全表且无新增 Gameplay 导出，实验另加本卡允许项。实验隔离对照分别给新自由函数移除 `CUEXIS_PLAYBACK_API`，以及在 `experimental`、`detail` 命名空间各额外导出一个未列函数，前者应在安装消费者或仓内 shared host 链接、缺符号检查失败，后者应由导出门禁按限定名拒绝。
4. 兼容新增与执行协调组后继退役各自从 `candidate-shared-debug` 执行 `cmake --build --preset candidate-shared-debug --target cuexis_player cuexis_host_protocol_tests cuexis_execution_host_tests`。在 `tests/rpa/CMakeLists.txt` 注册 `rr_sdk_execution_host_shared`，用 `ctest --test-dir out/build/candidate-shared-debug --no-tests=error -R '^rr_sdk_execution_host_shared$'` 验证真实 Player 装配只载入同一个实验 Playback 共享库及 owner/fence/Pause/Resume/close 行为。默认及候选安装消费者均不能包含 `execution_host_access.hpp`；实验库检查所有允许的内部 symbol，额外内部 symbol 阴性失败；默认库无该组导出。退出复验仅删除批准组旧符号，复跑同一 shared Player 与内部导出探针。

5. reference-host staging 在合法输入与真实操作失败两支验证正确退出/报告，不能因等 Playback Failed 而挂起，旧消费者仍可编译。逐组记录兼容新增、实际过渡发布、替代稳定性和独立安装消费者证据；缺发布证据时保留旧面并交 T-09 具名处置，不虚构发布、不重新裁定 D-19 原则。F306/F405 关闭及 F510 晋升须分别满足对应退出/接受条件，不能因 facade 或候选测试通过直接标关闭。

- F310 复用本卡四配置安装消费者及精确导出门禁，逐项对齐“安装声明全集→分类决定→实际动作/受保护保留”。同工具链对照受影响类布局、枚举值、类型身份和旧头独立消费；新 facade 与原入口使用同一类型，内部头安装不可见。每类至少有适用正反例，并将各项关联至对应检查；公共退出仍须实际过渡发布和稳定证据。缺声明、无分类或有未批准兼容破坏即不通过；清单与对照均收入原证据目录，不新增常驻维护表或测试框架。

- T-04 移交：候选 hooks 独立拆分。`playback_session_gameplay.cpp` 与 `playback_session_prepare_gameplay.cpp` 的 hook 入口要独立成文件、让默认闭包完全不看见候选 hook 声明，必须调整内部头或公共头边界；T-04 的卡面禁止本轮改公共头，因此保留现状并登记。本卡与 RR-F122 的候选宏、安装面和逐符号迁移同批处理：拆分后默认闭包不含候选 hook 声明，实验闭包每个 hook 仍只有一个定义，用 T-04 的 `cuexis_rr_playback_isolation` 与安装消费者同一套证据核验。

- replay 身份正反例在原 Playback/RPA 测试消费迁移后同一内部头，结果与卡前字节一致。全 app 的直接 engine/src 引用数为零；相对路径、尖括号、未许可 internal 及内部头误安装各有拒绝对照。许可限定实际消费文件及头，不增加目录通配；合法 shared host 可消费现有内部接口，外部安装消费者不能包含它。T-14 接续完成搬迁后再核全应用与反向依赖。

## 证据

`out/review/stage-07-rr/T-08/` 保存四个安装配置的清单、两个导出配置各自的 preset/工具链及 T-06 原表、当前符号表与差分、正反消费者与 shared Player 日志、逐组发布/稳定证据和后继移除清单。

## 停止条件

默认或窗口内的实验旧消费者失效、共享类布局漂移、旧符号提前消失、表列接线符号缺失或出现未列明的内部导出时恢复卡前安装面。执行协调组有跨库未解析调用或 shared Player 行为回归时，保留该组的旧已装入口，推迟该组退役。
