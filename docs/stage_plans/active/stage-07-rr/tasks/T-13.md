## 步骤

1. 按[源输入](../contracts/prepared-artifact.md#源输入与-lowering)接 `chart_v5_loader.cpp` 与 `compiled_source.cpp`：唯一 `objects` 场景、CXT v1 动画与 CXT v2 实体/玩法投影、full E 与 K4 owner、初始和触发资源闭包。用 T-12 的 `BeatGameplaySourceView.timing` 精确绑定 map；同一 view 按 stable merge 传完整 `patternDefinitions` / `measureDefinitions` typed spans（含未用项）及原声明/引用，产出 owning 未终结表。消费 T-12 已创建且已完成旧头转引的 `compiled_gameplay_context.hpp`/`compiled_gameplay_rows.hpp`，身份与 Stable ID 继续取 T-10 运行值头；本卡只提取 Graph limits、绑定校验和 shared visitors，并隔离 read/source/legacy build-interface 根。
2. 实现 SCN1/BHV1/ANI1、TIM1/JPR1/RES1、header/目录及两个 Reader；从独立声明核对锚键、关系、程序、JPR1 每实例选表和单元资格、GPD0 空声明等级、原 GRC0 resource terminal 位及静态基数。源与 Reader 共同调用 `finalizeCompiledArtifact`：闭包和 hash 校验后派生身份、准备运行索引。Reader 不查作者源或回放输入证明，不链接作者、旧 Capsule 实现或 Playback。 源入口比每个 K4 与 `common.chartEntryId`；两 Reader 按首条检查所有 K4 的逻辑 ID 一致，零条不推导，仍核 owner、来源闭包、镜像、自摘要及给定的 expected，不推断原作者声明。作者 `camera` 投影到 Graph 的 `staticChart.defaultCamera`。
3. 三路共用一个运行消费路径，实际 view 用 SCN1 默认相机 TRS，按已存及动态 tick 求值循环、Stop、混合和 Step；后继 FactBinding 消费 `SettlementEvent.direction`。按[接线合同](../contracts/prepared-artifact.md#schema工具与接线)交付 v5 作者壳、CXT v2 玩法包络、Graph2/entry v2 schema 和 CXC metadata/manifest。`cxc` 在旧 bootstrap JSON loader 之前登记候选目录并分派命中的 bootstrap；检查闭包后才显式选择，普通自动默认不选后继条目。`cuexis_gameplay_assemble beat-us` 调用同一 source adapter，按选定载体写成品和 metadata；发布只在完整校验后原子替换。
4. 按[载体、目录 producer 与 Playback 工厂](../contracts/render-player-writer.md#命令与启动)实现 `playback::detail::CompiledSourceAccess::fromArtifact`：声明 `engine/playback/internal/cuexis/playback/compiled_source_access.hpp`、实现在 `playback_source_gameplay.cpp`、`PlaybackSource` friend、仅实验 shared 内部导出。松散工程与 CXC 复用 v2 directory 读取规则；把已终结的拥有型成品及该快照的 provider/assets 交工厂核对后移入，进入现有 prepare/commit。工厂不重解码或重编译。T-15 调用本工厂，不另建载体工厂；公开 Playback 布局与旧工厂保持原样。
5. 在原 `engine/gameplay_packed/CMakeLists.txt` 中、旧目标之后依次创建 `cuexis_gameplay_packed_read`、`cuexis_gameplay_packed_source` 及合同 aliases；根在 engine 完成后进入 tools。消费 T-10 的 `cuexis_gameplay_author_cli`，仅给 `cuexis_gameplay_author` 追加 `PUBLIC cuexis::gameplay_packed_source` 和根 `ALLOWED`，新 CLI 分支仍由原 `src/assembler_cli.cpp` 编入 CLI 目标。按合同同步 active-target、实验 static 实际闭包与边守卫，不另建 `gameplay_packed_read/source` 子目录或把 CLI 放回作者库。
