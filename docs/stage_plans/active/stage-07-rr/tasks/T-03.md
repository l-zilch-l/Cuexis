## 步骤

1. 将各项归到对应 Reader/Writer，其中 CRC 和 CXC profile 沿已有 D-25，GridDelta 保留测试覆盖，CXT v2 记录显式工具调用。给 R1 前的 Packed/CXC 现行实现加对照。Chart Beat 文档引用 `ChartLimits::maxBeatNumeratorMagnitude` 和 `maxBeatDenominator`。RR-F121 将对照说明分为宿主可观察的默认版本摘要与内部定版本测试。
2. RR-F131 按入口解释既有诊断：普通规范化只生成有序的观测；旧执行 profile 按其 §8 判定整批提交；RPA 按 occurrence 槽与 T2 规则接纳。三者分别取证，保留旧 profile 的首错次序和 Replay 行为。对 candidate 安装及宏头列出已采用合同和现状 diff，供 RR-4 限定迁移。
3. RR-F122 交付现存 `materializePresentation` 默认安装证据。对照 `app/execution_host/frame_observation.cpp` 和 `app/player/src/player_execution.cpp`，为 RR-F135/F142 各列当前触发、诊断及可观察失败。RR-F135 另绑定已批准映射：实际分配失败使观测桥操作失败用 `host.rpa.allocation_failed`，真实配置预算/容量拒绝才用 `host.rpa.capacity_exceeded`；纯观测丢失标 Unknown/不完整且不阻塞 Gameplay，操作失败不得伪报完成。列明当前实现与该合同的差异，移交 T-06 的既有 FaultSlot Reason、持续 OOM 下错误交付及副作用对照验收；不在本卡实施或重开已接受裁定。其他错误表变化或 Packed 双入口统一作为具体发现移交，退出前按验收页登记去向与恢复条件。

4. RR-F132 对照 `execution_kernel_prepare.cpp` 的实际身份构造，区分 engine 的算法标记与 ruleset/session 的配置身份。绑定改动前旧 fixture 的身份字节、token 与 preimage，交 T-10 作迁移对照；不凭旧描述搬移身份字段、替换后缀或重算历史身份。

## 任务级验收

- 实施时用 `cmake --preset candidate-debug --fresh` 及 `cmake --build --preset candidate-debug --target cuexis_chart_tests cuexis_cxc_tests cuexis_judgement_tests`。将下列名称注册到对应测试目标，再逐个执行 `ctest --test-dir out/build/candidate-debug --no-tests=error -R '^<测试名>$'`。
  - `rr2_contract_packed` 用同一可读样本，前 92 字节 CRC 通过，把 Header CRC 换成旧文档算法结果时报 `packed.header.crc`。另用现有 fixture 变换 TIME 与 REQ0 的 mode，保持 envelope 和 section CRC 正确，mode 0 可读，mode 1 分别报 `packed.time.invalid` 和 `packed.requirements.codec`。
  - `rr2_contract_entry` 让静态 profile 的 `packed-chart`、Behavior profile 的 `source-json` 各自通过，交换 encoding 经 `validateCandidateChartBytes` 报 `cxc.chart_entry.entry_invalid`。原 CXC 默认项仍可读。
  - `rr2_contract_beat` 在 v1–v3 Reader 以最简有理数分别取权威上限及上限加一，其余字段合法。边界通过，越界为 `chart.beat.limit_exceeded`。分子测试包括符号两侧。
  - `rr2_contract_input` 分开驱动下面的普通入口和旧执行 session；保留 `execution_profile_tests.cpp` 现有旧 profile 断言。RPA 使用已有 `cuexis_rpa_tests`，不将普通 journal 当作成功的生产 submit。
