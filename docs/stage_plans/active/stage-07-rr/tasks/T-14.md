## 步骤

按[完整准入矩阵](../contracts/render-player-writer.md#完整准入矩阵)的既定纯值定义扩展 `PlayerCommandContext`：保留原成员，追加 `hasActiveContent/hasConfiguredSource/initialLoad/realtimeGameplay` 与 `pauseAdmission`（`PlayerPauseAdmission`）。`PlayerCommandDecision` 追加 `effect`（`PlayerCommandEffect`）和 `successPolicy`（`PlayerSuccessStatePolicy`），枚举、默认值和所有分支按合同，不另设结构。`evaluatePlayerCommand` 只作准入和策略选择，owner 从 A、来源、首装尝试、用途及暂停记录构造 Context；`initialLoad` 首次受理即耗尽。事务中 PendingNewRun/CurrentRun Pause 与已确认 AlreadyHeld 按合同区分。owner 在提交时读取实际设备确认、pending Pause/剩余原因和故障，才发布成功态；`apply` 撤销末尾无条件 `state_=decision->state`，只递交原 channel 并消费 terminal。Fixed 也只能在实际工作成功后提交。T-15 只消费本卡命令和终态。

1. 迁移设备校正与起播钳位；在原枚举末尾追加 `PlayerCommandKind::Retry=8`，不改既有编号；`playerCommandName` 返回 `retry`，`evaluatePlayerCommand` 沿[命令状态矩阵](../contracts/render-player-writer.md#所有权暂停与收尾)处理 Retry；Retry 等待设备确认期间，合格 Pause 送 owner 合流，不能被通用 transaction-in-progress 检查提前拒绝。`PlayerController::apply(PlayerCommand)` 把具名请求送唯一控制者并读终态；由控制者使用缓存来源开新局，沿原 `OwnerChannel`、terminal/ACK 消费，不与 Reload 复用重读路径。唯一控制者串行处理命令、暂停原因、无音轨表现尾和自然结束。开局先预配一个 P 槽 `GameplaySettlementBuffer`，沿 A 的 `SessionSettlementCommand/Reply` 和原 terminal/ACK 移交；满槽拒绝不丢 buffer、不推进。worker 的首个 poll 移出 owning reply，重读只得 `SessionSettlementStatus`。
2. `execution_scheduler.cpp::tryStart` 的真正 seal 同步写槽及 outcome；即时 request 与后来由 capture 完整批片/prefix 触发的 Waiting 使用同一投影。`session_worker_dispatch.cpp`、`ExecutionHost::flush/advance` 与 `execution_host.cpp::awaitSession` 消费触发该 seal 的回复，先交事件/取 score，后处理 decision/错误并 ACK；query/retry/retire 不补取、不重发。Pause drain、Resume 在 cut 的 Hold 中断 seal、Stop 同接槽和 StepKey；故障也交已封前缀。
3. NEXT Resume 用已验证 prepared 选 `ResumeEpochPolicy::keepRun`：host 只增 segment/controlSequence，RunKey 不变；同改 `validNextContext` 的 preflight/accept、capture route、Playback 和 scheduler 守卫。用原 operation/StepKey、pauseEpoch、trace cut/digest 和旧/新完整 context 核验，成功后才 enableOrdinary。legacy 仍增 epoch；同局不得重置 canonical ingress、advance/command 序号、Fold 或结果交付标记。
4. Stop 预检并阻止普通推进后关闭 capture 路由，收齐最后批片及 epoch end，在 kernel 接收仍开放时完成编号，再 query 真实上界；`detail::advanceStopCut` 原子核对后才关闭 kernel 接收并 seal。已暂停 Stop 复用冻结边界。EOF 以校正后的逻辑位置接续单调时钟，实际推进判定尾。先交当次事件，再从首次 `SessionSettlementReply.outcome` 中的 `GameplayAdvanceOutcome::score` 移交一次 `CompletedRun`，后撤路由、清局，保留 A/健康音频。已经自然结清的局 Stop 复用已保存终态。清理失败只重试未清步骤，完成前不提交新局。旧迟到、期限及失效时钟用例通过替代验证后才退旧控制权。

接收游标直接消费 T-10 的 producer：`ExecutionScheduler::deliver` 在完整批片及 occurrence 检查后调用 `detail::receiveCanonicalBatch`，以回填的真实 sequence 保存 admissions，Resume trace 使用同一 kernel 编号器。Playback Stop 在预检后先 `acceptControl`、关闭 capture route 并收齐已确认最后批片/epoch end，再在同一 owner 事务调用 `detail::acceptedIngressThrough(session, run)`，把返回上界和已验证 cutoff 交 `advanceStopCut`；其再次校验上界后才关闭 kernel 接收并 seal。禁止从 `confirmedSequence()`、capture delivery、输入个数或已产生 fact 推算上界；不得通过 host DTO 或测试私有字段代填。普通/Paused、空前缀/序号 0、重投/Resume 的状态均由该链负责。

## 任务级验收

Stop 使用 [runtime/timing](../contracts/runtime-timing.md#prepared-与当次推进) 的终止记录、事件和计分合同，整谱分母取自当前 prepared；本卡不创建另一套投影或回放格式。 验证 `CompletedRun` 的 v3 分支拥有完整 `GameplayNormalizedScoreResult`，含真实零分和整谱分母；旧 query/Fold 路径不得为 v3 取分。判定先结清、设备 EOF 未到时显式 Stop，仍只交付已取得的终态值一次。

P4-01 的命令矩阵及纯值验收归本卡：在 `tests/player_support/player_command_tests.cpp` 扩展既有 `Every application state and command pair follows the published table`，覆盖 6×8、Failed 有/无 A、配置来源、首装耗尽、实时 Seek、三种 Pause 准入以及 effect/successPolicy，更新已有 busy/duplicate/Failed/Reload 的旧预期。执行 `cmake --build --preset headless-debug --target cuexis_player_support_tests` 与 `ctest --preset headless-debug --no-tests=error -R '^Every application state and command pair follows the published table$'`；单元测试只验证纯准入，不把 decision.state 当设备成功证据。下列 `rr_session_control` 验证生产 owner 对策略的实际提交，包括 P4-07 设备确认前后收到 Pause、设备失败、同来源 pending 重投、Resume 剩余原因、Rebuild 尚有非画面故障；每请求一次终态，提交前零错误成功态。P4-01 的 CLI/窗口/R、F5 路由归 T-15，不能把本卡矩阵实现推迟到键位接线。

- 实施时新增、当前未执行：`ctest --preset candidate-debug --no-tests=error -R '^rr_session_control$'` 执行[向量 P4-03–05、P4-07、P4-11–13](../contracts/render-player-writer.md#所有权暂停与收尾)。P4-07 由 headless 调用方经同一生产 `OwnerChannel` 提交 `PlayerCommand{.kind=PlayerCommandKind::Retry}`；设备确认挂起时再提交来源 11、12 的两条具名 Pause。成功时新 epoch 直接静音 `Paused@0`，三请求各有一次成功终态；只解除 11 仍暂停，解除 12 后只起播一次。事务失败时三者各收一次失败终态、同一 cause、无新局。不以 `static_cast` 枚举值、测试私有命令或伪造回执代替。旧回执不复活旧局，输入边界不可证或 Fold 故障不发正常成绩。清理前复制同局成功 Stop 内存归档，对照 CLK-02 做重放；不重发事件或成绩。注入结果交付后清理失败，重复 Stop/EOF 不重结算；清理仍未完成时 Retry/Reload 不提交。交付的拥有型结果清理及卸载后仍读得到。
- P4-11 必须驱动真实 request/capture/worker：H=115、close=15，prefix=100 仍 Waiting，prefix=101 的 capture reply 才带原 advance #20 的 Hit@90/Miss@100；即时执行对照同值。首次 poll 取 payload，重读只有状态，query/同请求重投/retire 无事件；消费先于 capture/session ACK。注入槽不足、post 满及 seal 后 Fold 故障，分别证明无推进与已封前缀保留；只有一个 P 槽 buffer，不新增结果队列。

- 同样新增、当前未执行：`ctest --preset candidate-debug --no-tests=error -R '^cuexis_rr_compiled_clock_contract$'` 执行[向量 CLK-01–03](../contracts/runtime-timing.md#验收向量与任务前置)。按 CLK-02 分层构造的真实 capture 对照：六条无义务 release、release@89、press@90 实际生成 ingress 0–7，最后 observed=91 不越过 C=100；加入 prefix 使 capture delivery 上界与 7 不同。Stop 的生产 query 仍得到 7，封至 100，只交 Hit@90/Miss@100，不补未到期项；独立普通 `advance(100)` 对照只封至 85。缺批片拒绝且无虚构上界，重投不增加编号，锁后 tick 95 无编号、无归档、不结算。105/90 未来 pending 场景保留在 T-10 内核验收，不伪造实时未来证明。校正得到 EOF 锚 500000 µs 后推进注入单调时钟，活动 elapsed 199999 µs 不结束，200015 µs 封到最后义务 tick 700000；暂停时间不计入，不用模拟“已完成”通知替代推进。过期身份或无效时钟不推进。覆盖 Paused Stop 复用已闭合前缀、接收序号 0 与空前缀不同、Retry 后旧输入 epoch 和旧 Stop/EOF 回执均不影响新局。覆盖未播放即 Stop 无成绩、空/静态无音轨在首轮推进完成、有限表现/玩法义务取后完成者、活动无限表现须 Stop。
