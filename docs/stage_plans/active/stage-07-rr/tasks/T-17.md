## 写域

`engine/playback/src/playback_session_prepared.cpp`、`engine/playback/src/playback_session.cpp`、`engine/playback/src/playback_session_prepare.cpp`、`engine/playback/src/playback_session_internal.hpp`，以及 `tests/playback/` 的对应用例和 `tests/playback/CMakeLists.txt` 注册。不改公共头、安装面、wire、诊断码和候选宏布局。

## 步骤

1. RR-F509：`PreparedPlayback::State::owner` 是裸指针，materialize 时直接解引用，会话先于 Prepared 销毁即 UAF。改为 `weak_ptr` 或 generation 校验；若改动对宿主可见的语义，先按 D-04 取得裁定。
2. RR-F508：`unload()` 未清 `hostFence`、`acceptedHostControl`、`confirmedHostContext`、`executionMapping`、`tailTransition`。补齐清理，并覆盖 unload 后再次 commit 的状态泄漏。
3. RR-F501：GameplayOnly 的 `valid()` 与 `commit()` 对同一会话给出不同结论。接受集由 D-04 裁定后落到实现；未裁定前只补测试与现状登记，不改语义。
4. 三项共用两个文件，拆分给子代理时按 F509 与 F508+F501 两段分别提交、顺序合并，避免同文件并发写。

## 任务级验收

- 实施时新增、当前未执行：在 `tests/playback/CMakeLists.txt` 注册 `rr_session_prepared_owner`、`rr_session_unload_state`、`rr_gameplay_only_accept`，再用 `ctest --test-dir out/build/headless-debug --no-tests=error -R '^(rr_session_prepared_owner|rr_session_unload_state|rr_gameplay_only_accept)$'` 执行。
- `rr_session_prepared_owner`：会话先销毁、后 materialize 必须返回受检错误而非 UAF；反向顺序保持可用。
- `rr_session_unload_state`：unload 后五个字段清零，再次 commit 读不到上一局状态；前后状态各取一次对照。
- `rr_gameplay_only_accept`：`prepareGameplayLoad` 之后 `valid()` 与 `commit()` 给出同一结论。D-04 已裁定时按裁定断言；未裁定时只记录现状并标未裁定。
