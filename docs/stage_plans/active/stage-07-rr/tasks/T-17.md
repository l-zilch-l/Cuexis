## 步骤

1. RR-F509：`PreparedPlayback::State::owner` 是裸指针，materialize 时直接解引用，会话先于 Prepared 销毁即 UAF。先核对现有 `PreparedPlayback`/`PlaybackSession::State` 的移动与唯一所有权关系，再加最小内部寿命守卫：只有原会话仍存活且身份匹配时才允许解引用，失效时返回既有受检错误。公共头、对象布局、移动行为和既有错误码保持不变；不引入完整所有权框架或任意新错误码。若最小守卫必须改变公共所有权或 ABI，停止该条并按 D-04 取得裁定。内部采用 token/generation、内部 lease 或其他不改变外部边界的机制，留到实施时依源码关系选择，本卡不以预设算法作为执行前提。
2. RR-F508：`unload()` 未清 `hostFence`、`acceptedHostControl`、`confirmedHostContext`、`executionMapping`、`tailTransition`。补齐清理，并覆盖 unload 后再次 commit 的状态泄漏。
3. RR-F501：按已接受修订，让 `PreparedPlayback::valid()` 依据实际内容类别识别合法 Presentation/GameplayOnly；空、移后、错线程对象无效。有效 GameplayOnly 的 `contentInfo()`、`semanticIdentity()` 和适用音频访问按实际内容可用，依赖 presentation 的操作独立检查能力。`valid()` 不保证 `commit()` 成功；提交仍独立检查 owner/session、generation、lifecycle、在途操作及 host fence。正例限定为同一合法会话且准备后的提交前置未改变；分别验证对象无效与提交资格失效，删除两者在所有条件下同结果的断言。
4. RR-F435 仅追踪到上项 F501：合法 GameplayOnly 可以 Ready 且无 World，内容有效性与表现能力分别判断；不增状态或重复测试。
5. RR-F203 在登记前按已有属性类型/值域规则检查全部 writes；全部通过才发布可用 token 和整批覆盖，失败沿既有错误返回，无部分覆盖，不改变既有覆盖及可观察状态。保持合法 token 的 release/lifetime 规则；不要求 token ID 连续或所有内部计数不动。对象之后失效、同优先级冲突等仍按原求值合同处理，不能将登记成功等同于未来 update 必定成功。
6. Playback 三项保持原验收，Runtime 登记校验单独取证；同文件改动顺序合并，避免并发覆盖。

## 任务级验收

- 实施时新增、当前未执行：在 `tests/playback/CMakeLists.txt` 把 `rr_session_prepared_owner`、`rr_session_unload_state`、`rr_gameplay_only_accept` 注册到现有 `cuexis_playback_tests`。先执行 `cmake --build --preset candidate-headless-debug --target cuexis_playback_tests`，再用 `ctest --test-dir out/build/candidate-headless-debug --no-tests=error -N -R '^(rr_session_prepared_owner|rr_session_unload_state|rr_gameplay_only_accept)$'` 核对三项注册，随后用 `ctest --test-dir out/build/candidate-headless-debug --no-tests=error -R '^(rr_session_prepared_owner|rr_session_unload_state|rr_gameplay_only_accept)$'` 执行。默认 preset 不开启候选宏，不能作为本卡验收入口。
- `rr_session_prepared_owner`：在未选定生产内部算法前，使用可控失效寿命输入或等价的预失效内部状态，断言 materialize 返回既有受检错误且解引用计数为 0；另用真实会话销毁后再调用 materialize 的顺序，核对同一受检错误，最后释放 Prepared，验证实际接线与守卫寿命。反向顺序仍保持可用。测试不得依赖释放内存的偶然内容、机器速度或事后 crash，也不得把普通 debug 运行宣称为内存安全证明。
- `rr_session_unload_state`：unload 后五个字段清零，再次 commit 读不到上一局状态；前后状态各取一次对照。
- `rr_gameplay_only_accept`：按上述 typed Packed → `prepareLoad` 的真实路径创建 GameplayOnly，另设合法 Presentation 对照，覆盖以下分支。

| RR-F501 场景 | 必须断言 |
| --- | --- |
| 两类合法准备对象 | Presentation 与 GameplayOnly 各自 `valid()==true`；同一合法会话且提交前置不变时各自 commit 成功。GameplayOnly 不创建占位 Runtime/World。 |
| 对象无效 | 空对象、移后源对象、错线程查询均 `valid()==false`；移后目标在 owner 线程仍按实际内容有效，析构遵守已有线程规则。 |
| GameplayOnly 内容及音频访问 | `contentInfo()`、`semanticIdentity()` 返回实际准备的内容；分别构造有/无音频的候选，有合法音频时 `mainMusicSource()` 可用，无音频时返回既有缺失结果，不把缺音频当作内容无效。 |
| 表现能力独立检查 | 有效 GameplayOnly 在依赖 presentation 的访问/操作上仍按既有缺失/拒绝规则处理；保留真实用例的无 World 帧/update 拒绝对照，不由 valid 推断可呈现。 |
| 提交资格独立检查 | 从独立候选状态分别验证 owner/session 不符、generation 过期、lifecycle/在途操作或 host fence 不允许时的既有拒绝；至少保留一例内容仍有效、`valid()==true` 但 commit 被拒绝，核对无成功提交副作用。不得为追求 valid/commit 等价放松这些门禁。 |

- RR-F203 在现有 `cuexis_runtime_tests` 扩展 override 用例：合法 Host 与 StudioPreview 批次可登记并整体生效；在独立夹具分别放入类型错误及既有值域拒绝值，包含“合法首项、非法后项”，均无可用 token、无部分覆盖，既有 token 的效果和可观察状态不变。不调用 release 清理失败批次也能继续合法 update，随后可登记合法批次并正常 release；原 RemainingFrames、UntilChartTimeMs 生命周期用例继续通过。用例值及诊断取现有属性校验，不创设新值域；不以 ID 无间隙或全部内部计数不变验收。实施时 `cmake --build --preset candidate-headless-debug --target cuexis_runtime_tests`，再用 `ctest --test-dir out/build/candidate-headless-debug --no-tests=error -N -R '(override|Override)'` 确认原生命周期及新增登记用例均匹配，去掉 `-N` 执行且保留 `--no-tests=error`。
