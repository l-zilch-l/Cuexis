## 2. S2 — S6-A2 合同落盘与 S6-B1 版本门禁（PR #26/#27）

**结论**：A2/B1 的主线成立——`check_version_gate.py` 分离「当前版本一致性 / 相对基线前进 / 发布日有效性」，
比较规范化 `(year, month, day, build)` 四元组；trusted baseline 由受保护 `master` 取得，
版本显示值 `26.09.27-1` 与 `vcmake/CuexisVersion.cmake`、`vcpkg.json` 一致
（`python -B tools/update_version.py --check` 通过）。以下为缺口。

### SPEC-03 [中] historical 复验上下文形同虚设

- **现象**：`tools/check_version_gate.py:105-106` 的 `--context` 只做枚举校验；
  live 与 historical 走完全相同的日期规则。
- **spec**：计划 §S6-B1 第 3 条「历史 SHA 的复验使用其记录的发布上下文，不因复验发生在另一日而要求重写历史」。
- **证据**：`tools/check_version_gate_tests.py:97-104` 只断言 `result.context` 的取值，
  传入当天日期同样通过。
- **影响**：历史复验语义未实现，复验可能以错误日期基准放行或被误拒。
- **处置建议**：让 context 真正参与日期规则选择，并补一条"历史上下文 + 非当日日期"的用例。

### SPEC-04 [中] 门禁自身修改不被任何在库用例发现

- **现象**：`tools/check_version_gate_tests.py:19`、`:199-229` 读取的 workflow 来自 `TRUSTED_ROOT`，
  即基线里的副本；候选对 `.github/workflows/version-gate.yml` 的修改不被任何在库用例发现。
- **spec**：ADR 0042 第 321 行要求「修改门禁本身需要代码所有者复核与独立负例」。
- **证据**：全仓检索 `CODEOWNERS` 0 命中；B1 报告第 45 行只说明"workflow 自身从 trusted baseline
  materialize"，真正执行的 job 定义仍来自候选。
- **影响**：门禁的自我修改没有实际保护；"受保护门禁"的强度低于报告表述。
- **处置建议**：引入 `CODEOWNERS` 或等效的 workflow 变更保护，并把该保护的实际生效证据写进报告；
  仓库无权限时按计划要求列为阻塞项，而不是以本地脚本通过代替。

### SPEC-05 [中] 缺少可执行的竞争与缺基线负例

- **现象**：`tools/check_version_gate_tests.py` 的 11 个用例中没有任何并发 PR 竞争用例；
  缺文件/缺基线路径只用字符串断言（`:216`、`:224-228`）或全零假 SHA（`:168-177`）。
- **spec**：计划 §S6-B1 验收段要求「同一 UTC 发布日…缺失基线、两份版本不一致、两个 PR 竞争、
  跨日重新发布与历史复验负例/边界」。
- **影响**：`version.bootstrap.required` 这条关键分支没有被真正执行过负例。
- **处置建议**：为"仓库缺少 checker/test/workflow"与"两个 PR 竞争"补可执行负例，
  并把它作为 B1 门禁的一部分长期运行。

### SPEC-06 [低] 同日 build 耗尽时诊断语义错

- **现象**：`tools/check_version_gate.py:134-137` 在同日 build 已达上限时先抛
  `version.build.exhausted`，抢在 `version.unchanged` 之前。
- **影响**：诊断码与真实原因不符，调用方按码分支会得到错误归因。
- **处置建议**：调整判定顺序或在诊断中同时给出原因。

### SPEC-07 [中] A2 表征不全且未纳入自动门禁

- **现象**：`tools/check_stage6_a2.py:245-263` 只表征 `S6-D01/D02/D04/D06`，
  `S6-D07`（版本门禁）与 `S6-D08`（SDK 与宿主）无表征。
- **spec**：计划 §S6-A2「以下八项已由 ADR 0042 固定…形成独立 golden 和最小表征」；
  第 171 行「所有新增合同必须可测试」。
- **证据**：全仓引用 `check_stage6_a2.py` 的只有它自身与报告，未注册进 CTest 或 CI

- **影响**：4/8 项冻结决策没有表征兜底；脚本不会在任何门禁中被执行。
- **处置建议**：补齐 D07/D08 表征，并把脚本注册为 CTest 用例（计划已声明它是手工门禁，
  但"可测试"要求未满足）。

### SPEC-08 [低] `--event` 无规则消费

- **现象**：`tools/check_version_gate.py:292`、`:331` 的 `--event` 只用于打印。
