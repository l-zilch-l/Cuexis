## 5. 缺陷

本批次发现并修复的缺陷全部是**门禁与打包自身**的缺陷，不是 SDK 行为缺陷。实现报告 §5.3–§5.5 记录
过程，这里只列结论与修复提交：

1. `dc4b16a`：清理过的 `PATH` 在宿主运行之后没有恢复，后续 configure 找不到资源编译器；外来
   toolchain 负例没有带正例使用的 vcpkg 依赖解析参数，于是因缺少 `tl-expected` 而不是因工具链不一致
   失败。
2. `a38d6cc`：MinGW 下宿主运行以 `0xc0000135` 失败——清理环境缺少编译器运行时。门禁现在把
   `libgcc_s_*.dll`、`libstdc++-6.dll`、`libwinpthread-1.dll` 复制到可执行文件旁。
3. `716b697` + `d7980bd`：hosted 的六个插桩 job 只失败 `cuexis_reference_host_staging`。原因是
   Cuexis 用目录级 `add_compile_options`/`add_link_options` 施加 `-fsanitize=address,undefined` 与
   `--coverage`，这些选项不进安装导出，外部工程按 `find_package` 链接被插桩的 static SDK 时缺少同一
   套插桩（`undefined reference to __gcov_*`、`__asan_*`、`__ubsan_*`）。第一次修复把参数挂到了
   **错误的** `add_test`（Player 分发门禁，它不链接任何目标），CI 原样复现失败，靠检查
   `out/build/debug/CTestTestfile.cmake` 确认参数没有进 staging 门禁；第二次挂到正确位置，并把
   `--coverage` 追加到 `CMAKE_CXX_STANDARD_LIBRARIES`，避免 `-lgcov` 早于静态库导致的链接顺序问题。
4. 版本门禁：起始顶端 `aa73630` 的显示版本过期，本批次推进到 `26.09.27-1`（`dfc5842`，`vcpkg.json`
   同步）。
5. 打包实现期：`cuexis_player_dist` 必须登记进 `CUEXIS_ACTIVE_TARGETS`，且必须登记在 warnings 循环
   之后，因为自定义 target 不可编译（`target_compile_definitions called with non-compilable target
   type`）。
6. 许可证清单：vcpkg 中构建 `nlohmann_json_schema_validator.dll` 的 port 的 `share` 目录不带
   `copyright` 文件，因此必需许可证集合是 10 个 port 而不是 11 个；该决定与理由写在
   `cmake/PackagePlayer.cmake` 的注释里，同一上游项目的许可证文本仍随 `json-schema-validator` 一起
   分发。

## 7. 残余与边界

- hosted 的 Player **分发**门禁只在 Windows（MSVC、MinGW）注册：Linux preset 是 headless，不构建
  Player，因此 Linux 只覆盖宿主门禁。
- 宿主二进制的符号级检查（导入表与依赖清单白名单）还不是门禁；当前证明是「只链接
  `Cuexis::Playback`、只包含公共头、在清理 PATH 与源树之外运行成功」。把导入表纳入门禁属于 F1。
- 插桩 preset 的宿主门禁依赖「把父构建的插桩选项转发给外部工程」这一约定；它在本机与 hosted 都
  验证过，但不是安装导出的一部分，将来新增插桩类型时需要同步维护。
- 真正的磁盘满、只读介质与配额失败仍未取证（E3 残余，属于 F1）。
- GPU、窗口与真实音频设备下的宿主与 Player 行为不在本批次内；§4 的 `--smoke-test` 是本机一次真实
  GPU 运行，不是 CI 证据。
- 升级示例验证的是「重新构建」路径，不承诺 shared binary 的可替换性，也没有实现配置迁移（两个配置
  格式当前都只有 v1）。
- 本批次没有改 SDK minor、没有合并 PR、没有写 Stage 6 关闭报告，也不构成 owner acceptance。

## 9. F1 可消费的 C4 交付与边界

R5 §10.1 与 §10.2 的允许与禁止消费清单继续生效，且**不被本批次扩大**；下面只列 F1 可以直接使用的
C4 交付物与不得越过的边界。

可以消费：

- `cuexis_reference_host_staging` 与 `cuexis_player_distribution` 两个门禁，以及 `cuexis_player_dist`
  打包命令，作为 F1 最终 SHA 验证的一部分。
- `examples/reference_host/` 作为「安装包加公共边界」宿主的模板，以及它记录的运行判据（身份
  `6d01494c...` 与帧摘要 `11596562486377158370`）。
- SDK 安装树与 Player 分发目录作为 F1 的验证对象；`VERSION.txt` 与 `cuexis-player-dist.txt` 的 flavor
  元数据作为安装与部署的判据。
- `docs/guides/VERSIONING.md` 的升级示例、破坏性变更说明与回退边界，作为 F1 版本与部署检查的基线。

不得消费：

- 把 `examples/reference_host/` 当作 SDK 交付面或公共 API；它是宿主模板，内部结构不是承诺。
- 把 `cuexis_player_dist` 的输出目录提交进仓库或当作发布产物；它是构建期生成的本地证据。
- 用 candidate 开关产出任何分发目录或安装树；candidate 仍是构建树内的实验路径（R5 §10.1 不变）。
- 在 F1 与 F2 的证据和 owner 决定之前宣称 Stage 6 关闭、周期验收或 owner acceptance。
- 把本机 GPU `--smoke-test` 当作 CI 证据，或把 headless preset 当作 Player 分发验证。
- 通过 umbrella target 把 Player、Studio、测试或后端依赖带入宿主；`CuexisConfig.cmake` 的组件边界
  必须与实际链接边界一致。
