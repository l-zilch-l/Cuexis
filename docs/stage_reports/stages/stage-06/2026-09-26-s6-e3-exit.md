## 2. 计划项对照

计划 §S6-E3 第 1 项（分离四类身份，原始资源与 provenance 不进运行时闭包）：

- `cuexis.media-provenance` v1 单行 canonical JSON 同时记录 `rawSourceIdentity`（原始编码字节
  SHA-256）、`profileIdentity`、`artifactIdentity`（canonical 产物 SHA-256）、`assetId`、原始
  字节数、作者侧 locator 与精确 decoder。测试断言原始输入身份不等于产物身份。
- sidecar 写在 generation 的 `provenance/` 子目录，**不在**运行时闭包列表里；Playback 不读它。
  未知键、重复键、错误版本、路径化的 AssetId、与产物字节不符的 identity 一律拒绝而不是修复。

计划第 2 项（缓存键覆盖全部影响结果的输入，命中复验，损坏稳定拒绝，不由 Playback 静默再导入）：

- 键是 domain `cuexis.media.cache.key.v1` 上长度前缀 preimage 的 SHA-256，preimage 含原始输入
  身份、profile 身份、decoder 家族 token 与输出相关构建策略
  （`minimp3-no-simd;fp-precise;contract-off`）。
- 命中时记录与请求逐字段复验，再按内容地址重新哈希产物；损坏、被编辑、引用不存在产物或语义
  不完整的条目都以 `media.cache.corrupt` 拒绝，不作命中处理。只有 `--rebuild` 才显式离线重建。
- Playback 不链接该库，运行时也没有任何再导入入口。

计划第 3 项（staging → 验证 → 单一发布点，进程间锁，失败清理与重启恢复）：

- generation 是内容寻址的不可变目录 `generations/<identity>`，身份覆盖 label、运行时闭包与
  provenance 列表（domain `cuexis.generation.closure.v1`）。
- 顺序是：校验请求 → 取锁 → 独占创建 + `fsync` 写 staging → 写 marker → 重新读取 marker 并
  **逐条重算摘要** → `fsync` 目录 → **一次 `rename`**。任何失败路径都删除 staging。
- 相同内容重发是经验证的 no-op；同身份但字节不同是 `asset.publish.conflict`，不覆盖。
- 锁是操作系统级句柄独占锁：writer 崩溃由内核释放，因此重启恢复不需要 stale-lock 超时；第二个
  writer 得到 `asset.publish.busy`；锁文件存在本身不代表持锁。
- `recoverPublicationStaging` 清理被遗弃的 staging 与临时文件；`adoptGeneration` 是显式的、
  只写 `cuexis.adopted` 的独立调用，从不改写用户工程入口。

计划第 4 项（同一批产物建立 v4 与 candidate 闭包，失败不覆盖上一有效包）：

- `publishPackagePair` 从同一批条目构建两个闭包（candidate = 共享闭包 + candidate 专属条目），
  **两者都构建并通过生产加载器自校验后才触碰任何目标**。
- 替换写同目录临时文件（保留 `.cxc` 扩展名）、用 `CxcPackageLoader::loadFile` 复验字节并比对
  包身份，再备份/替换；替换失败恢复备份。candidate 替换失败时 v4 目标被**逐字节恢复**到替换前
  的字节（此前不存在时才删除），因此失败既不产生半更新的包对，也不丢失上一有效包。

### 2.1 验收 ID S6-G12

计划 §3.1 对 `S6-G12` 要求「媒体 provenance、缓存、资源 closure 和发布事务完整」，必需证据为
「缓存损坏/失效、磁盘/替换/并发失败、旧包和活动会话保留」。逐项对照：

| 必需证据 | 结果 | 证据 |
| --- | --- | --- |
| 缓存损坏 | 拒绝且不重导入 | 库用例（损坏记录、被编辑 profile、被破坏产物、冲突记录、显式 discard）+ CLI 门禁（坏记录、旧 profile 身份都返回 `media.cache.corrupt` 与非零退出码） |
| 缓存失效 | 键变化即不命中 | 库用例（其它 profile / 其它 decoder / 其它构建选项 / 不完整输入都不命中）+ CLI 门禁（`--rebuild` 显式重建） |
| 磁盘/替换失败 | 失败不产生部分结果 | 注入钩子覆盖 staging、发布前、替换前与指定目标替换失败；另有非注入用例：`staging`/`generations` 被同名普通文件挡住时拒绝且不留残余，包目标位置是目录时以 `invalid_request` 拒绝且不改动目录 |
| 并发发布 | 第二个 writer 被拒 | 同进程与**跨进程**两个用例（跨进程用例重新启动同一个测试二进制持锁），第二个 writer 得到 `asset.publish.busy`；CLI 门禁覆盖带陈旧锁文件与被遗弃 staging 的重启恢复 |
| 旧包保留 | 失败不覆盖上一有效包 | 替换失败保留上一有效包的字节与身份；pair 中 candidate 失败时 v4 目标逐字节恢复；candidate 闭包非法时两个目标都不动 |
| 活动会话保留 | Playback 不受影响 | 发布事务库只依赖 `cuexis::core` 与 `cuexis_cxc`，不在 Playback/Player 的链接闭包内；`developer-tools` OFF 的默认 `debug` 全量用例通过，安装消费者不依赖媒体解码库 |

## 5. 缺陷

实现与 hosted 期间发现并修复的缺陷全部记录在
[实现报告](2026-09-25-s6-e3-publication-transaction.md) §5，本页只列退出相关的两条：

- hosted Windows MinGW 在 `0753e6a` 之前失败于 `undefined reference to '__imp__dupenv_s'`：库与
  测试按 `_WIN32` 选择了 MSVC CRT 扩展。改为按 `_MSC_VER` 选择（与仓库既有写法一致），并在本机
  加入 UCRT MinGW 语法检查以在 hosted 之前发现同类差异。
- candidate 替换失败时原实现删除 v4 目标，会丢失上一有效包。现在替换前捕获 v4 字节，失败时
  逐字节恢复；另有包目标不是普通文件时的拒绝，避免 `rename` 静默销毁一个目录。
