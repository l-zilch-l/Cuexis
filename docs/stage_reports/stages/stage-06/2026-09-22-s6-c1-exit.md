## 2. 计划项对照

C1 的生产链已经接上，并且默认构建仍关闭它：

1. 显式 `fromFilesystemProjectEntry`、`fromCxcFileEntry`、`fromCxcMemoryEntry`
   拥有 package bytes。OFF 构建返回 `playback.candidate.disabled`，不读取输入。
2. entry 选择和唯一一次 `packed::decode()` 在 `cuexis_cxc`。工具层调用同一生产校验。
   失败不会改去读取同包 v4。
3. Playback prepare 复用已经校验的 typed semantic，不重新 decode，不转 v4 JSON，
   不展开 CXT v2。
4. typed lowering 保留 identity、parent、Requirement 和 resource closure，并把
   alpha 转为 opacity。generated execution ID 对上 A2 golden。
5. prepared identity 使用 `cuexis.prepared-semantic.v5.candidate.1`。v4 identity
   函数和 FrameDigest golden 没有改。
6. A16 仍由 chart 内部离线 assembler 承担。candidate prepare 拒绝 host parameter，
   不在 Playback 中重编译。
7. 16 MiB entry 限制和 40000 entity/requirement 上限仍由既有 Packed/CXC 门禁执行。
   本次没有新增 40k candidate prepare 的进程内存测量，也不把 40k 写成任意内容的
   内存承诺。
