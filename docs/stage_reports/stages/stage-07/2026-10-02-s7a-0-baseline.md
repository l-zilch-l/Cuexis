## 3. 首次基线尝试的失败与权限处置（如实保留）

首次 `cmake --preset debug --fresh` **失败**，原因不是代码或配置：

```text
error: fopen("C:\Users\Zilch\AppData\Local\vcpkg\downloads\PortableGit-...part"): permission denied
CMake Error ... file failed to open for writing (Permission denied):
  D:/Cuexis-worktree/out/build/debug/vcpkg-manifest-install.log
CMake Error: Cannot open file for write: D:/Cuexis-worktree/out/build/debug/CMakeCache.txt
EXITCODE=1
```

实测确认：工作区根可写，但 `D:\Cuexis-worktree\out`、`out\build`、`out\build\debug` 写入被
Windows 文件权限拒绝。

处置：运行仓库自带的工作区权限诊断脚本（`diagnose-windows-sandbox-acl`），对
`out\build\debug` 及其两个父目录补回当前用户的完全控制权限，并逐项复验：

```text
SUMMARY FIXED=0 GRANTED=3 REFUSED=0 RESTORED=0
verifications: 3 × status=verified
nextAction: verify_original_confined_operation
```

复验后四个层级（工作区根、`docs`、`out`、`out\build`、`out\build\debug`）写入均成功。
脚本的备份与恢复脚本保存在 `D:\Cuexis-acl-recovery\`（3 组 `acl-backup-*.json` 与对应 `.ps1`，
报告 `acl-report-faf60127ed594ecfb83142b8e90f9c10.jsonl`）；如需回退，按报告中的 `ROLLBACK`
命令逐条执行即可。

随后会话文件策略变为完全访问，vcpkg 才能写入工作区之外的下载与 registry 目录。
**基线的可复现前提因此是：工作区（含 `out/`）对当前用户可写，且 vcpkg 可写其下载目录。**
首次失败日志不被改写为成功。

### 4.2 唯一失败项：`cuexis_contract_version_gate`

| 项 | 内容 |
| --- | --- |
| 失败测试 | `cuexis_contract_version_gate`（`tests/contracts/CMakeLists.txt` 注册的 Python 契约测试） |
| 失败用例 | `test_bootstrap_shell_fails_when_the_trusted_tree_lacks_the_gate`（`tools/check_version_gate_tests.py:587`） |
| 直接复现 | `python -B tools/check_version_gate_tests.py` → `Ran 19 tests ... FAILED (failures=1)` |
| 表观诊断 | `AssertionError: 0 != 1 : the extracted bootstrap block is not executable shell: ::error title=Version gate bootstrap required::version.bootstrap.required: trusted baseline  lacks ; ...` |

**根因（已定证，不是仓库缺陷）**：

1. 默认 `PATH` 上的 `bash` 是 `C:\Windows\system32\bash.exe`，即 **WSL 启动器**。
2. `usable_posix_shell()`（同文件第 52-99 行）只用 `"wsl" in Path(shell).name.lower()` 排除该
   shim，而该文件名是 `bash.exe`，因此**未被拒绝**；它的 `git --version` 探针在 WSL 内成功
   （`/usr/bin/git` 2.53.0），于是函数返回了这个 shim。
3. 测试随即用该 shim 执行从 `version-gate.yml` 提取的 trusted-baseline bootstrap 块，Windows
   临时仓库与 WSL 文件系统视图不一致，产生**假的 `lacks <file>` 诊断**并把正例判为失败。
   该文件第 60-65 行的注释正是对这种现象的描述。

**反证**：把 Git Bash（`C:\Program Files\Git\bin`）置于 `PATH` 首位后，同一条命令
`python -B tools/check_version_gate_tests.py` → `Ran 19 tests in 7.8s` / **`OK`**。

**归属**：登记为缺陷 D-9（测试守卫未覆盖"WSL 启动器名为 `bash.exe`"这一常见情形），
主题归属 version-gate，与 Stage 6 交接收口第 4 项相关；它**不阻塞 S7A-0**，但必须在 S7A-8
的 version-gate 回归中先消除，否则同 SHA 证据会带上一个环境噪声失败。
