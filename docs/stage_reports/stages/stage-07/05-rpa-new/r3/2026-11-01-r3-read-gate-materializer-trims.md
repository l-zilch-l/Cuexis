## 1. 改动

只动 `engine/playback/src/presentation_materializer.cpp`，两处：

1. **比较后再赋值**：`object.materialAssetId.assign(appearance.material)` 改成"不相等才赋值"。
   赋值一个相等的字符串在语义上是空操作，但每帧每对象都要付一次写。
2. **逐对象 id 比较降为长度比较**：`read->id != entry.id.value` 原本每对象比较一次完整 id（36 字节）。
   现在**每帧第一个对象仍做完整比较**，其余对象只比较长度；"这份布局属于这个运行时布局"的权威判据是
   每帧一次的 stamp 检查（owner + layout + version），逐对象比较本来就只是第二道网。

两条都不改输出：digest、布局校验、资源映射与错误码都不变。

## 2. 局部 A/B（同版本补丁对照）

1800 实体、每块 4000 次操作、九轮交替，每帧成本：

| 项 | 基线 | 裁剪后 | 比值 |
| --- | ---: | ---: | ---: |
| extract（纯读块） | 101.95 µs | 91.37 µs | **0.8962** |
| update+extract | 176.95 µs | 165.55 µs | 0.9356 |

两侧都下降——不是把成本搬进 update。

同一轮里还试过一个反例：把 id 比较换成一个预计算 64 位哈希字段。它让 `ObjectVisualRead` 从 72 字节涨到
80 字节、布局条目也变大，实测 extract 反而 **1.0782**（更慢）。所以最终采用的是"首个对象完整比较 +
其余长度比较"，而不是加字段。
