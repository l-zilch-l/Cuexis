## 2. 四项裁定

### 2.1 本轮不运行 hosted CI

本轮不执行 hosted CI，也不做同 SHA 的远端验证。hosted 同 SHA 的**未验证状态原样保留**，
不因本轮未运行而记为通过、豁免或降级；本地 11/11 同源矩阵仍只是本地结果（见 §4）。

### 2.2 D2 / D3 / Snapshot / 排队：接受“可开关阶段计时 + 归因 + 开销披露”作为登记方式

裁定：owner 接受该登记方式作为这四项预算的判定依据。判据不变（D2 ≤1 ms、D3 ≤2 ms、
Snapshot ≤2 ms、排队 ≤1 ms），被替换的只是“只能记未判定”这一条。

登记结果：

| 阶段 | 判据 | 每进程 p99（3 进程） | 每进程中位 | 判定 |
| --- | --- | --- | --- | --- |
| judgement（D2） | ≤1000 µs | 45.8 / 122.2 / 46.8 µs | 13.2–13.7 µs | **通过**（余量 8–22×） |
| projection（D3） | ≤2000 µs | 17.9 / 19.2 / 19.1 µs | 8.9–9.5 µs | **通过**（余量 >100×） |
| runtime（D3 提交侧） | ≤2000 µs | 6.0 / 6.4 / 6.2 µs | 3.6–3.8 µs | **通过**（余量 >300×） |
| snapshot 物化 | ≤2000 µs | 11.0 / 18.4 / 12.2 µs | 5.7–6.3 µs | **通过**（余量 >100×） |
| queue | ≤1000 µs | 26.2 / 88.4 / 40.2 µs | 11.9–12.2 µs | **通过**（余量 11–38×） |

登记方式的操作定义（以后同类阶段预算沿用同一套，四条须同时成立）：

1. 计时设施由编译期开关控制，关闭时不进入产品路径；开启即改变二进制，必须如实标记。
2. 只登归因读数，逐进程报 p99，不改判据、范围、样本规则或失败保留规则。
3. 必须用同负载对照披露插桩开销。本次对照为 `request→ready` 中位 303.0 对 270.5 µs，约 **+12 %**
   （p99 522 对 538 µs，在噪声内）；把 12 % 全算到各阶段上，上表余量仍成立。
4. 不与任何无插桩预算读数混用，不据此替换外层端到端门，也不据此发布容量结论。

边界：读数来自单独建树 `out/build/pd-metrics`（Release，`CUEXIS_PD_METRICS_TEST_ONLY=ON`）、
设备探针 1200 帧流式负载、3 个进程；这是本机、本构建、本会话的单次登记，不追加样本到过线。
该例外只覆盖这四项；其他预算仍按“缺少无插桩边界记未判定”执行。

### 2.3 40K @ 240 FPS：接受“结构性不可能”的判定

裁定：owner 接受该判定为最终结论，按计划 §12.2 选项 2 处理（明确改变适用能力范围）。具体含义：

- 40K 不再作为“240 FPS”这项能力的适用规模。判定文本与全部读数保留、不改写，也不删减证据。
- 240 FPS 的边界仍以冻结容量值（1080p 仅渲染 1800、静态 1300）与实测前缘括区表述；括区在不同源码
  与仪器下分别是 [2400, 2600) / [2200, 2300) 与 [3600, 3800) / [2600, 2800)，都是诊断值，
  不做点间插值，也不发布新容量值。
- 判定依据保留：1080p、`466ff76`、真实 OpenGL 可见窗口下 40K 入镜实体完整周期 p99 为
  50.282 / 61.325 ms，是 4.166667 ms 预算的 12.07× / 14.72×，需再快 10.71× / 13.71×；
  降分辨率无效（720P 同二进制对照），唯一被测量的架构杠杆（实例化）只值 1.32×。
- 40K 的首次可响应 2,821–3,029 ms 与首帧 2,148,938 µs 不因本裁定改判，仍按原记录保留；
  owner 此前已裁定 40K 属测试极端情形，两个口径不合并。
- 不因此关闭 R4、设备接受或生产接受；本裁定只改变“240 FPS 适用于哪些规模”。

### 2.4 内存：接受预算超过 128 MiB

裁定：owner 接受内存预算超过 128 MB，128 MiB 不再作为 R3 的适用上限判据。

登记结果（两个口径分别登记，不互相替代）：

- **40K prepare 私有峰值**：最小 254.7 MiB，按实测登记，不判超界。
- **续点预算计费**：244,028,048 B；同一构建的实际多留为 323,303 B，计费高估 755×。
  高估本身作为待修正的证据保留，不因接受超出而消失。
- **六代全开**：实际额外 requested 约 1.18 MB。
- 本裁定**不设新的数字上限**；通用 caps 与 profile 的正式注册仍归 R4 / PD 线，未由本裁定升级。
  `docs/stage_reports/stages/stage-07/04-pd/pd-5/` 的历史判定与冻结 caps 保持原样。
