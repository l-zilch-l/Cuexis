## 1. Pause 超界：根因是进程第二次 SwapWindow

用探针的三段时间戳（`start_us` / `confirmed_us` / `first_present_us`）把首次 pause 拆开，再在探针里
临时把冻结绘制拆成 sample 与 present 两段，并对那一帧开 GPU timer：

| 段 | 读数 |
| --- | ---: |
| `host->pause(clock)` | 258 µs |
| 冻结帧 `sample`（CPU 构建快照） | 49 µs |
| 冻结帧 `present`（SwapWindow） | **175 836 µs** |
| 该帧 GPU 命令范围的 timer query | **1.024 µs** |

也就是说：CPU 不慢、GPU 不慢，179 ms 全在交换。接着做了两个判别：

| 判别 | 结果 |
| --- | --- |
| 隐藏窗口 vs 可见窗口 | 178.7 ms vs 182.8 ms —— 与窗口可见性无关 |
| 先画 1 帧 live 再 pause | 停顿**转移到那帧 live**（174.9 ms），首次冻结绘制只要 **713 µs** |
| 先画 2 帧 live 再 pause | 同样转移（177.4 ms），首次冻结绘制 236 µs |

结论：这 175–190 ms 是**本进程第二次 `SwapWindow`** 的一次性停顿，与"冻结"无关。登记负载里第二次
present 恰好就是第一次 pause 的那一帧，所以超界落在 pause 名下。同一批运行里，交换链已经热起来之后的
pause 是 0.4–0.9 ms。

因此：读数对"登记负载"是诚实的，但根因不在 pause 路径，而在交换链的一次性建立。

## 2. 读取相对门：根因是逐对象读 registry 的内存流量

先做量级判断：差距随实体数线性增长（每实体 5.6–8.6 ns），所以是逐对象成本。然后用四个消融实验定位，
每个都是"同一提交内的补丁 vs 原二进制"三对交替比较：

| # | 改了什么 | 比值（补丁/原） | 结论 |
| --- | --- | ---: | --- |
| E0 | 去掉逐对象 `Result<ObjectVisualRead>` 与重复窗口验证 | 1.0175 | 没有收益，略慢；已回滚 |
| E1 | 完全不读 registry（行结构保持不变，写入路径不变） | **0.8247** | **整个差距都在逐对象的组件读取里** |
| E2 | 只去掉 `registry.valid(entity)` | 1.0068 | 校验不是成本 |
| E3 | 改成运行时内部的批量读（每块 32 行，循环对编译器可见） | 1.0392 | 更慢；调用边界与内联也不是成本 |

E1 把 B 从约 206 ms 拉回到 170–180 ms，正好是 pre-PD 臂（A）的 175.9 ms。也就是说差距全部来自
"每帧、每对象、从 registry 读一次 transform（64 B 矩阵）与 appearance（可见性、材质、不透明度、tint）"。
E2/E3/E0 说明它不是校验、不是调用边界、不是 `Result` 包装；把这些都去掉没有用，只有把**读取本身**
去掉才回到 A 的水平。

一个可核对的算术旁证：B 比 A 每对象多触碰一份 `ObjectEntityMap` 条目（约 40 B）与一次间接索引，
1800 对象就是约 72 KiB/帧；按本机内存带宽量级折算约 7 µs/帧，而实测差值是 15.4 µs/帧——同一量级，
剩余部分很可能来自指针追逐带来的额外未命中（这一点是估算，未单独测量）。

**这不是一个能在局部修掉的代码缺陷。** 要闭合它需要数据布局层面的工作：测量两臂每对象的实际触碰字节、
并决定展示读取是否允许携带一条紧凑的预聚集行。后者会动读取合同，属于 owner 范围的改动，不是本地补丁。

## 3. 两个根的处置建议

| 项 | 根因 | 可执行处置 | 是否需要 owner |
| --- | --- | --- | --- |
| Pause 179 ms | 进程第二次 SwapWindow 的一次性停顿（GPU≈0） | 启动后第一帧之后再 present 一张预热帧，把停顿留在 load（2000 ms 预算，当前 410 ms）里；`first_frame_presented` 边界不变，因为预热帧在它之后。或者另登记一个"先跑 N 帧再 pause"的负载并同时报两个读数 | 否（预热帧）/ 是（改负载登记） |
| 读取 1.1732 | 逐对象读 transform+appearance 的内存流量 | 先做数据布局实验（每对象触碰字节、紧凑预聚集行的可行性），再决定是否改读取合同 | 是 |

## 边界

- 消融比较是同一版本内的补丁对照，不与 pre-DD 臂的正式比值相加，也不作为门读数；三次成对比较只用于
  判断量级，不足以做显著性结论。
- 预热帧实验是在探针里做的，不是产品改动；它证明停顿可以被提前吸收，不等于产品已经这样做。
- Pause 的正式读数仍以第二批报告为准（超界），读取相对门仍以第一批报告为准（1.1732 超界）。
