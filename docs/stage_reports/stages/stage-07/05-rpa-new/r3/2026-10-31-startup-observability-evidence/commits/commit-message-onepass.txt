Parse JSON in one pass instead of through a callback DOM

`json::parse` built a complete nlohmann DOM through a parse callback and then copied every node
into `Value`. On the 13,171,906-byte 40K chart that cost 10.05 s, and the attribution probe shows
where it went: the same document parses in 0.24 s without a callback, a callback that does nothing
but return `true` costs 9.87 s, and the product's duplicate-key observer costs the same 9.87 s. The
observer was never the cost; the third-party callback-mode parser was, and the value copy after it
added the remaining 0.2 s.

The one-pass builder already exists for the formats that state owning-value budgets.
`json::parse` now validates the caller's text budgets and delegates to it, so nesting depth,
string-byte ceilings and duplicate-key rejection are enforced by the same reader that builds the
tree, and neither the third-party DOM nor the value copy remains.

The owning-value budgets stay unbounded because this entry point's callers state text budgets only.
Inventing container or value ceilings here would reject documents that parse today, and every
caller that wants such a budget already calls `parseBounded` directly.

- `json.parse` of the 13.17 MB chart 10,048.80/10,055.03 ms -> 971.64/924.41 ms
- `ChartWriter::writeCanonicalJson` 11,074.06/10,900.44 ms -> 1,896.71/1,810.44 ms
- semantic identity unchanged: 936c32eede42abfbd136e217591c623b3ba3dc7093694fe60a356e070f656869
