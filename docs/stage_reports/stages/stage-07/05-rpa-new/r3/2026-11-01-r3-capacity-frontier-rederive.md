## 为什么重推

冻结的 1080p 括区是 `8e275a5`、探针 `daa0c3cf…` 上测出来的：仅渲染 2400 通过、2600 失败，静态
2200 通过、2300 越过悬崖。此后中立路径 CPU 杠杆落在 `6256af8`，它把每帧的 CPU 提交成本压掉约三分
之一——那组数字是另一个仪器测的，见
[中立路径 CPU 杠杆](2026-11-01-r3-neutral-path-cpu-lever.md)。前缘有没有跟着移动，只能在同一份
源码上重新推一次；把两批数字相减不是测量。

## 方法（预注册，先于测量）

- 预注册在 16:31 写定（`frontier-rederive-preregistration.json`，sha256 `900c32e2…`），在任何一次
  测量之前：10 个实体数、执行顺序、通过判据、两个预测模型与锚点规则都写在里面，事后不改。
- 每点 = 三个全新进程 × 20 s × 1920×1080，同一条固定命令；`CUEXIS_GPU_BARRIER=1`、`TIMER=0`、
  `PIXEL_READBACK=1`、`WARMUP_MS=2000`、预热 8 帧；进程 BelowNormal、亲和 65535、执行节流关闭。
- 通过判据逐字取自冻结登记：每个进程 wall FPS ≥ 240、cycle p99 ≤ 4.166667 ms、每个完整 1 秒窗
  ≥ 240 帧，三点全过才算该点通过。个别超预算帧只作信息记录，不翻转判定。
- 顺序 `1800, 3000, 2400, 3400, 2600, 3600, 2800, 3800, 3200, 4000`：升序与降序交错，避免半小时
  内的机器漂移被读成规模效应。
- 每个点只跑一次，不重采样；驱动在探针二进制哈希变化时中止。本次十点的 `binary_sha256` 全程一致。
- HEAD 在首个点之前从 `6256af8` 移到 `a93c979`（文档整理提交），按预注册自己的条款重新登记：补记
  记录这次移动只含 `docs/` 与 `tools/verification/check_docs.py`（45 个文件、114 插入 / 111 删除），
  预注册文件字节未改，探针哈希复测未变。

## 这两个括区意味着什么、不意味着什么

- **意味着**：在这份源码、这个探针、1080p 与这个夹具上，仅渲染的 p99 到 3600 仍在预算内
  （4.1490 ms，占预算 99.58 %），到 3800 越界（4.3380 ms，104.1 %）；静态到 2600 仍在预算内
  （4.0698 ms，97.68 %），到 2800 越界（4.4369 ms，106.5 %）。静态在 3000 及以上还同时踩到
  "最小秒窗 < 240 帧"那条规则，所以它的失败不是单帧 p99 一处越界。
- **不意味着**"3600 实体可以 240 FPS"这样的正式容量结论。冻结的确认列表（1080p 仅渲染 1800、
  静态 1300）仍是唯一确认的容量声明；本阶梯是诊断括区，不做点间插值，也不做点间的显著性检验。
- **尤其不能**把 3600 与冻结阶梯的 2400 相减说成"+50 % 容量"：两次测量的源码、构建、会话与探针
  都不同，差值同时混入了四个变量。

## 与冻结阶梯的方向性对照

| 项 | 冻结阶梯（`8e275a5` / `daa0c3cf`） | 本次（`6256af8` / `6b01a30f`） |
| --- | ---: | ---: |
| 1800 仅渲染 p99 | 2.7479 ms | 2.3452 ms |
| 1800 静态 p99 | 3.5700 ms | 3.0316 ms |
| 仅渲染括区 | `[2400, 2600)` | `[3600, 3800)` |
| 静态括区 | `[2200, 2300)` | `[2600, 2800)` |

预注册的锚点规则是方向性检查而不是效应量：1800 仅渲染 p99 中位数 2.3452 ms 低于冻结阶梯的
2.7479 ms，所以本次阶梯可以作为本源码上的诊断括区报告；反过来，`verdict.json` 里对刷新会话
（`3210.5 µs` / `3725.1 µs`）的相对差 −26.95 % / −18.62 % 只说明"这次和那次不是同一台仪器"，
`binary_matches_refresh` 为 `false`，不得当作杠杆的效应量引用。

## 预测的结局

- **仅渲染**：预测 `[3600, 3800)`（模型 `p99(N) = 1145.8 µs + 0.821625 µs/实体`，交叉点 3676），
  实测与之一致。
- **静态**：预测 `[3000, 3400)`，实测 `[2600, 2800)`，**被否证**。预注册自己写的 caveat 说明该模型
  把冻结阶梯的静态悬崖按实体数等比平移，而冻结阶梯已经显示静态带有一份与实体数无关的固定每帧
  成本；实测把这条 caveat 变成了可量化的偏差——平移模型高估静态成本约两档。

把预测写成"事后总能对上"没有意义，这里保留否证的那一半。

## 失败与未覆盖

- 没有无效点、没有重采样、没有作废尝试；十个点各跑一次，全部 `valid`。
- 未覆盖：1080p 之外的任何分辨率；GPU 时间戳（本批 `TIMER=0`，只有 CPU 墙钟）；其它构建与其它
  探针；4000 之上不再取点（4000 已失败，再往上不改变括区方向）。

## 边界

- `test_only`：不替换冻结的容量结论，不提升任何生产门限，也不构成 R3/R4、设备或生产接受。
- 每点三个新进程、每个二十秒：只支撑"该点在预算内/外"，不支撑点间差异的显著性。
- 逐点相对范围全部低于 15 % 的登记阈值（最大 13.71 %，静态 3400），因此没有任何点需要按"只用于
  通过/失败、不作为速度读数"的规则降级引用。
- 只在 1080p、该探针二进制与该夹具上成立；换分辨率、夹具或构建即属另一次测量，必须重新登记。
