# P8 low-reuse 变体：40,000 实体 + 4,096 行的完整规模单侧取证（2026-11-13）

状态：candidate evidence；单个进程的完整规模测量，不含重复性或接受结论

日期：2026-11-13

返回 [P8 40K 报告](2026-11-10-p8-40k-entity-memory.md)与

## 1. 这一跑是什么

P8 的正式内容口径是 `(40000, 4096)`。此前只跑过 high-reuse 侧；本轮补 low 侧，用探针自带的
`CUEXIS_PD5_REUSE=low` 开关——它把每条 requirement 的结束 tick 改成 `end+i`，竞争键、实体数、
内容行数与其余参数一律不变。

需要说清楚的一点：**low 是时间去相关变体，不是"无共享/冷缓存"负载**。域字节的对比因此只回答
"去相关是否改变内存占用"，不能外推成"低复用状态下的内存上限"。

构建：`--mode memory`（`CUEXIS_ALLOCATION_LIFETIME_OBSERVER=ON` +
`CUEXIS_EXECUTION_ALLOCATION_OBSERVER=ON`，其余插桩关闭），源码 `f5f9191`（`26.11.12-4`），
一个进程，exit 0，7.983 s，21 条断言。

## 2. 结果

总请求字节 **365,090,162 B**，其中 probe fixture/unclassified 21,574,775 B；活动分区精确
（34 个 cell、637,027 个活分配、0 个未标记）。

**没有任何域超出声明上限**（22 个 CPU 域全部比较）。占用率最高的两个：

| 域 | 观测 | 声明上限 | 倍率 |
| --- | ---: | ---: | ---: |
| `command.session` | 19,762,486 | 21,854,208 | 0.9043 |
| `steps` | 7,529,781 | 15,517,696 | 0.4852 |
| `execution.retained` | 141,080,535 | 1,327,497,216 | 0.1063 |

`gpu` 域仍是未测量状态（观察器覆盖不到）。

## 3. high 与 low 的对比

归档的 high 跑在 `2c4e1274`，与当前 SHA 不同，因此同时用同一构建、同一命令跑了 high 对照
（只改 `CUEXIS_PD5_REUSE=high`）：exit 0、7.883 s、总量 365,084,102 B，与归档的修正后 high 行**逐项一致**，
所以对比不受候选差异干扰。

| 项 | high | low | 差 |
| --- | ---: | ---: | ---: |
| 总请求字节 | 365,084,102 | 365,090,162 | +6,060（+0.0017%） |
| 23 个声明域 | — | — | **全部 0** |
| `packed_bytes` | 3,831,372 | 3,835,412 | +4,040 |
| `snapshot_bytes` | 9,266,672 | 9,266,672 | 0 |
| `frame_byte_bound` | 163,842,128 | 163,842,128 | 0 |
| probe fixture/unclassified | 21,568,715 | 21,574,775 | +6,060 |

**结论**：low 开关只让 requirement 的结束 tick 去相关，**不移动任何声明域**；全部差异落在 probe
fixture 桶里（其中 4,040 B 可由 packed 编码解释，其余 2,020 B 未进一步定位）。这不是通用的
"低复用"结论。

## 4. 边界

- 单个进程、单次运行；没有重复性、没有噪声口径。
- 不含 GPU/驱动、prepare-only 峰值、观察器扰动，也不检验 40K @240 FPS。
- 上限仍是 `budget-proposal.v1.json` 里的 proposed 数值（未接受），本文只报"在声明内"。
