# R4 首固定 CPU 组读取超界处置

状态：candidate；保留失败，未更改判据或开始新正式组

日期：2026-11-07

## 1. 已证明的事实

候选24f0a914的两个原固定单对象read-long组均在1.10全组门上超界，A/B重复性通过。
legacy为1.140031 [1.101273,1.180153]，RPA为1.146032 [1.128434,1.163904]。
36个测量进程、所有慢值、原语义/环境结果及attempt-1保留。legacy另外两指标存在重复性失败。
同一原始日志的cycle计数也上升约14%，还不能定位到某个函数。

本轮普通构建不执行extended observer；扩大census不是已证明的热路径原因。128-slot与
pre-PD相比也有变化，但没有同源单变量证据证明其是本次读取超界原因。
原R3大场景读门结果保持原范围，不能代替此固定单对象场景。

## 3. 推荐的诊断边界

不新增owner/线程/公开API/跨帧缓存，不借回退到旧中间版本作为正式A。保留普通allocator、
固定对象/viewport/输入、8块及既有read次数；诊断只比较同一候选的单变量开关或独立
源码副本，不替代正式样本。先记录源/构建/二进制、最大进程数和时限，在无本机构建或
压力任务的窗口执行；遇语义/身份/执行错误停止，不替样。

已接受R2借用范围、owner/serial/generation/首错和DTO污染恢复语义必须保持。若最小
处置需要新性能机制、第四R2机制、改变公共或借用语义，则先提交具体设计等待裁定。
无明确处置时不为凑通过使用第二次正式额度。A的日常合同内定位/修复由现有R4授权覆盖；
超出计划§4或触及上述边界的部分才需新增owner决定。
