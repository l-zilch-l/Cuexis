# PD-0 旧测量方法与诊断结论

证据日期：2026-10-16 至 2026-10-17；整理日期：2026-10-17

本记录合并已被替代的八份方法、追踪和停止点报告。旧原始测量与 ETL 已按 owner 要求删除，
本页只保留可以从原报告确认的结论，不再宣称旧路径可复核。当前摘要归

## 已确认的方法限制

- 本机早期时钟观测台阶为 0.1 μs；0.4 μs 的 15% 为 0.06 μs，短阶段相对变化容易受量化影响。
  嵌套插桩开销不能通过逐样本机械减常数消除。
- 旧 legacy profile 的 Replay 历史随同一 session 增长，不能通过不断增加预热/采样来代表固定工作量。
  后续改用 fresh session、固定轨迹和长读取块，并区分 legacy 与 RPA。
- recording OFF 仍可能来自编译了插桩的程序。旧 ABBA/BAAB 比较针对 recording，不能作为旧/新实现对照。
  新正式组改用编译插桩关闭、正常分配器、无 ETW 的独立构建。
- 含逐步正确性检查和 FrameDigest 的轨迹耗时不是纯 Playback 成本。

## 失败和归因边界

| 历史观测 | 允许得出的结论 |
| --- | --- |
| 早期六次诊断：默认 Projection 波动 40%，CPU 0 组各阶段最大 3.33% | 亲和性值得作为变量；不证明原慢运行原因 |
| 宿主 24 进程亲和性对照：默认最大 19.9231%，单核最大 32.0161% | 两组均未整体通过；不能把宿主统一绑单核作为修复 |
| 最终前置修复源码的单 owner 正式组最大 36.85% | 原组 inconclusive，未因后续较好结果改记通过 |
| 后续三轮追踪诊断共 12 个进程，十二项主指标最大 3.488% | 没有重现旧慢状态，追踪结果不能替代无追踪基线 |

CPU 0 曾观察到约 4.2%–4.4% 的设备中断占用；块级对齐也看到显示驱动的 DPC/ISR 与少量 Ready 等待。
这些信息只说明存在干扰，不足以解释历史慢组；频率、电源、温度与后台竞争仍未形成根因结论。
阶段单调用尖峰与进程间重复性属于不同指标，不能把两种极差百分比混为性能退化。

## 与已修复缺陷的关系

宿主定向诊断另外复现了 poll 与 wait 之间回复完成后仍等待超时，以及终端请求退役后 coherent
身份载荷未同步回收的问题。两者后来作为独立前置修复处理；机制和最终验证归
[等待与回收实施](../rpa/2026-10-17-retention-progress-and-wait-boundaries.md)，不能声称所有性能波动都由它们造成。

FrameObservationLedger 的完整帧槽位不回收仍是另一个问题，归 PD-4；容量 4 在第 5 帧、
容量 4096 在第 4097 帧失败，冻结 Tick 也可复现。未用扩大容量或删除回执规避。
旧 B5 Pause 的 capture_gap 与 CXC unpack 的 Access Denied 没有确定根因，本次整理不将其关闭。

## 保留的方法与未测项

QPC 外层块计时、源码/二进制/内容身份、完整电源参数指纹、固定实验预算及不删除慢样本的原则继续保留。
阶段插桩、分配探针和 ETW 仅作诊断；operator new 请求计数不是完整堆/GPU/驱动内存，逻辑复制不是硬件流量。
OEM/热状态、worker 有效 QoS、生产预算、实际设备、端到端 Seek 与 prepare-only/decoded heap 仍分别核验。
历史失败不构成生产通过或整个 PD-0 退出。
