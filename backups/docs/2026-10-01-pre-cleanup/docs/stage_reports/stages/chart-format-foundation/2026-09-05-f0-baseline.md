## 3. Foundation candidate lock

Foundation 只登记以下 candidate：

| 字段 | 冻结值 |
| --- | --- |
| Packed `packedVersion` | `1` |
| Header bytes | `96` |
| Directory entry bytes | `32` |
| Header `flags` | `1`（candidate） |
| Header `candidateRevision` | `1` |
| Candidate profile | `candidate.static-tap-lanes4-v1` |
| Requirement | `tap` + `point` |
| Judgement domain | `candidate.lanes4` |
| Required action | `press` |
| Constraint | discrete `lane`, range `0..3` |
| Foundation sections | `META`, `TIME`, `STR0`, `REF0`, `IDN0`, `ARCH`, `ENT0`, `REQ0`, `CNS0`，以及按实体组件需要的 `TRN0`、`REN0`、`CAM0` |

`REQ0` 的 half-open range 只冻结为 wire 形状，不表示 Foundation 支持 Hold/Release。
`BEH0`、`BHD0`、`ANM0`、`FXS0` 以及未登记的 RequirementKind、domain、action、constraint
和 codec 必须稳定拒绝，不能当作 opaque JSON 保存或播放。

Candidate 的语义层必须先得到 Canonical Semantic Chart；Packed Reader 不执行 CXT AST、
Parameter、Slot、Pattern、Repeat、脚本、随机数、宿主回调或上一帧状态。

## 4. 术语与身份边界

| 术语 | F0 解释 | 禁止混用 |
| --- | --- | --- |
| CXT Prototype | 作者层固定 Component/Requirement 生成规则 | 不是 Packed Archetype |
| CXT Instance | 一次带冻结 bindings 的 Prototype 调用 | 不是 Packed EntityRecord |
| Canonical Semantic Chart | CXT 展开后的具体 entity、parent、Component、Requirement 和资源闭包 | 不是新的 JSON 输入格式 |
| Packed Archetype | 已展开具体 Component 的共享默认值 | 不承载 CXT 槽位或 AST |
| IDN0 | 每个具体 entity 的运行语义 identity | 不能移入可删除 DBG0 |
| semantic identity | 展开后的规范语义 hash/input identity | 不直接等于 v4 source JSON hash |
| artifact identity | Packed 字节和 compiler profile 的 identity | 不替代 semantic identity |
| source/build provenance | 工具链来源与构建信息 | 不参与运行时语义恢复 |

## 6. 容量 profile 定义

三个 profile 的目标均为 40,000 个 CXT 展开后的 concrete entities，Packed file budget 为
`16,777,216` bytes。F0 只冻结复杂度定义；source bytes、section bytes、decoded bytes、
IDN0 bytes、prepare peak、耗时和实际通过/失败结果由 F8 产生。

| Profile | 复杂度定义 | 目的 |
| --- | --- | --- |
| `high-reuse-v1` | 一个 Prototype；10,000 个 Repeat group；每组 4 个 lane emit；每实体 1 个 point/tap requirement；Component 集合固定 | 验证 Pattern/Repeat、ARCH/default hit 和高复用字典收益 |
| `low-reuse-v1` | 40,000 个显式 Instance；每实体稳定且不同的 semantic identity、Beat、lane 和 position；每实体 1 个 point/tap requirement | 验证 IDN0、显式字段和低复用最坏方向 |
| `bounded-mixed-v1` | 20,000 个 Repeat 生成实体 + 20,000 个显式实体；固定 4 lane domain；每实体 1 个 requirement；资源引用集合受控且闭包完整 | 验证 Pattern 与显式实体的混合，以及资源/identity 记账 |

Profile 不能通过删掉 identity、Requirement、资源引用或降低实体数来“通过”。动画、行为、
效果和完整判定不属于 Foundation profile；Stage 8 必须另立 profile，不能把这里的静态结果
解释为任意复杂谱面保证。

## 7. 正反例与事务性要求

正例包括 empty、one-tap-lane2 和 16-entity stair；反例至少包括未知 revision/section、
非最短 varint、截断/重叠 range、CRC mismatch、UTF-8/identity mismatch、递归、缺 slot、
lane 越界、Beat/整数溢出、超 expansion count 和超 Packed bytes。所有失败必须在发布
semantic model、Packed artifact 或 Runtime 前发生，并保留旧 active 状态；不能产生可被
后续步骤误认有效的部分文件。

## 8. 交接与未决项

F0 交给 F1/F3：candidate revision/profile、术语边界、v4 baseline fixture 和禁止范围。
F2/F4/F5/F6 只能在此基线上增加独立实现，不得接入 v4 默认路径。F8 关闭前仍未冻结的项目

entry bytes。F9 仍需要 owner acceptance、dated completion report 和 Stage 6 handoff。
